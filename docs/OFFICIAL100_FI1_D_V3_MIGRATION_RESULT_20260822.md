# 第一创新点 FI1-D-v3：official100 冻结迁移评测结果

## 1. 最终结论

FI1-D-v3 已在最初用于第一创新点的 `official100` 固定五折上完成一次冻结迁移评测。全部输入适配、阶段 A/B/C-v2/D-v3、完整折外计划和最终 AP 审计均通过；未使用 GPU，未读取 `NCS-train100`、`NCS-validation60` 或 `ScanNet200 val312`，没有阈值、权重或方法扫描，也没有在结果出来后重跑 AP。

首要目标是类别无关主 AP。FI1-D-v3 的主 AP 为 `0.6758531686`，相对同次冻结 FI1-Legacy 控制的 `0.6768351734` 下降 `0.0009820048`，即约 `0.0982` 个百分点。因此，FI1-D-v3 **没有在 official100 上取代 FI1-Legacy 的主 AP 冠军地位**。

与此同时，FI1-D-v3 的 AP50 和 AP25 分别提高 `0.0087246720` 与 `0.0071925514`。这说明审计后方法更偏向提高较宽松重叠阈值下的召回与排序质量，但该收益不足以抵消高阈值区间的损失，不能表述为第一创新点主目标已经继续提升。

## 3. AP25 历史口径说明

本次控制的 AP 与 AP50，包括五个单折结果，均逐位复现 FI1-Legacy 历史值；只有 AP25 从历史 `0.8795907511` 变为 `0.8783051220`。

只读代码核查确认两次结果使用了不同的结果物化路径，并查到一处具体口径差异：

- 历史 FI1-Legacy 通过每场景缓存匹配记录 `_scene_records` 和 `_record_from_matches` 汇总 AP；
- 本次迁移从已经审计的规范冻结几何重新构造预测，并直接调用 ScanNet200 官方 `evaluate_matches`。
- 历史精简记录函数在计算可忽略预测时，把“小实例或组实例”写成一个 `or` 条件，交集只累计一次；官方评测器使用两个独立条件，同时满足时会累计两次。该差异会改变预测的忽略比例，且与只在较宽松 AP25 上出现差异的现象一致。

输入适配审计确认候选、类别、几何和历史分数均未修改；完整计划与保存数组的独立审计也均为零错误。因此该 AP25 差异登记为“评测器实现口径差异”，而不是方法变化。由于预注册禁止结果后重跑 AP，本实验不再另跑一遍历史 AP25 路径。D-v3 的正式增量只使用同一次、同评测器的控制与挑战方案；历史 FI1-Legacy AP25 继续原样保留，不覆盖也不混算。

## 5. 版本边界与后续规则

第一创新点现在必须保留为两套互不覆盖的代码与实验合同：

1. `FI1-Legacy`：代码审查前的历史冻结版本；仍是 official100 主 AP 冠军，也是现有 DM-SMS-1 的冻结几何底座。
2. `FI1-D-v3`：代码审查后按论文结论完善的独立版本；在 NCS-train100 OOF 上主 AP 正向，但迁移到 official100 后主 AP 略低、AP50/AP25 更高。

不能因为 official100 主 AP 未提高而删除 D-v3，也不能因为 AP50/AP25 提高而把它静默替换为现有系统底座。若未来继续研究第一创新点，必须提出新的独立假设并重新预注册；不得围绕本次 official100 结果扫描阈值、权重、追加数量或重跑 AP。当前第二创新点修补仍默认绑定 FI1-Legacy；将 D-v3 与第二创新点组合必须另建联合集成合同。
