## 一、修正研究判断

最新24场景A/B完整NT最佳IoU增量为0，说明没有提高这个候选池的逐目标最佳几何质量；不能推出最终AP必然不增。AP还依赖类别、置信度排序、实际候选预算、重复预测与匹配。原N有好mask但标签错、分数低或未入选时，一个稍差但被正确评分/分类的修补T仍可能恢复TP；也可能造成重复FP或挤掉好N。

## 三、任务2：借鉴Clutt3R-Seg的互补query关系诊断

### 1. 借鉴范围

论文III-B采用每帧包含树、跨视角叶节点分组、残余节点条件化父替换。我们先借鉴“多候选先建立同实例关系，再决定组合”，不把交叉重叠N/T/query强行变成树，不立即复制语义编码器、阈值、supervoxel输出或父替换。

保持原T父、halo、可见域、成员区域与P1先验。新建独立诊断目录。已暴露的旧28场景+本次24场景可作开发诊断，全部52场景的原T父纳入，不只挑4个已知GT机会。不得把它们当新规则的独立验收。

### 2. GT-free关系生成

对每父保留原top1锚query。候选query集合使用原父top2加每个可编辑父外整区的query均值top2，确定ID处理并列、去重；不使用GT选query。记录候选集是否遗漏潜在query，后置全部query参照只用于解释。

保存query—区域二部关系与候选query对关系；无需先建立完整实例树。优先记录：

- query对父主体及补点块的软支持、完整场景体积、父与halo内硬mask覆盖；原query和候选query的重叠、相互包含及新增支持。
- 原成员区域接触、候选query支持区域的空间联系；无重叠和有重叠分开，不能只用IoU筛掉真正互补的碎片。
- 既有最多六帧中，局部父支持区域和补点区域的共同/冲突mask证据；与之前“整父参考”分开记录。仅计算新的关系描述，不增加观测或硬门。
- 缺失/不可比较、未出现共同mask和存在明确冲突分开，不把缺失计负例。

同一query可支持多个区域、多个query也可支持同一区域；不能把它们当互斥实例分布。固定所有字段和候选集合并封存，然后才做GT关系诊断。

### 3. 后置问题与负例

全量报告而非只列成功案例，按物理场景、目标与query对分组：

1. 换另一个单query是否能同时解释父主体与缺失区？若能，是关联选择机会。
2. 是否只有多个query联合才能覆盖两部分？若是，是互补关系机会。
3. 相似关系是否也频繁出现在相邻不同实例之间？这是必要污染负例。
4. query候选已覆盖，但整区混杂导致无法安全编辑？这是区域表达问题，另列。

GT标签不能仅用“halo内主身份相同”即宣布同实例安全。分别报告父目标点、其他已知实例点、未标注点的覆盖与污染，以及组合后的完整NT增量；无法判定的关系保留unknown。局部与全场景身份区别必须明确，ROI不足时不作全局结论。

可以构造同域GT选单query/候选query集合的后置参照来判断信息供给，但绝不能混入推理结果。对小片段、低重叠互补、重复query和邻物关系分别分析，不只给总体AUROC；各query/块高度相关，不把条目数当独立样本量。

### 4. 本阶段输出与继续条件

输出关系数据、负例、场景级可分性、候选集合覆盖及真正池价值机会。此阶段不生成用于生产的新合并候选，不训练网络、不凭GT把query取并集。

若无GT字段能区分同目标互补与邻物，并保留多个场景的完整NT机会，再设计一个关联或分组机制；只改关联，先不同时改区域粒度与观测。新机制需要独立冻结验证，不能在52场景拟定后又称同批独立成功。
