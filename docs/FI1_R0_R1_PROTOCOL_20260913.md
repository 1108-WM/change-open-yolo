# R0/R1 首版共同协议（2026-09-13）

本协议在新 AP 之前制定。代码入口为 `tools/fi1_r0_r1_protocol.py`；运行产物保存协议 JSON、SHA256、代码与输入身份。它是待验证的直接评分参照，不是已有有效模型；参数尚未根据本轮 GT/AP 选择。200训练开发／55开发验证／5重叠诊断的角色不变。

## 几何与成员

两组固定本轮同一份 D-v3 点集及自身视觉证据。实际逐点核对原生缓存、全部历史成员及细化计划；PLY与processed XYZ顺序一致。相同点集只保存一份，但保留所有来源、原始类别和父子关系。几何来源与冻结上游的监督依赖分别记录。

- R0：保留原生已有前景类别、轨迹/并集已有前景类别，以及修正候选冻结类别。
- R1：保留R0成员，并为具有非原生别名的几何加入所有直接语义分数大于零的前景类别。纯原生几何不扩类。完整198维Alpha向量参与打分；没有新增每几何top-k阈值，也不压回top-1。
- 相同点集、相同类别合并成一条评测预测，原始别名完整留账。同点集不同类别不合并。该去重规则同时用于R0/R1，不能将其称为原历史600列的逐列重放。
- 背景/占位类`-1`、`198`不转成前景输出；空点集不输出，但保留账本。有效旧前景成员即使直接分数为零，也保留到统一预算环节。不额外设最小点数或NMS。

## 自身证据与直接分数

YOLO沿用原投影、标签图绘制及CPU `torch.topk` 可见性选择：每10帧采样，为每个自身几何选最多40视角，收集全部198类前景点票。分数为票数除以总前景票数。

Alpha使用自身几何的最多20个可见视角、SAM ViT-B框提示和最高预测IoU掩码、0/0.2/0.4三个裁剪尺度；按可见比例聚合归一化视觉特征，与全部198类归一化文本特征计算余弦。直接分布固定为`softmax(100 × cosine)`，100作为常见CLIP尺度预先固定，尚未验证其在本项目中的最优性。两种可用分布等权平均；只有一种有效时使用该种；两种均已提取但没有有效证据时返回零向量。几何质量及D-v3排序分数不乘入最终逐类分数。

未提取和已提取但不可用严格区分。Alpha尚未补齐时，预测构建器直接拒绝，不把YOLO单独结果命名为完整R0/R1。

历史Alpha缓存只能在点集、视角顺序、可见点数、投影框和三尺度裁剪一致时绑定；核对模型/词表/特征文件哈希并重算聚合与198类余弦。不使用历史SMS删除标记或Alpha第一名。历史导出没有记录RGB字节哈希，因此缓存复用明确标记`historical_rgb_content_identity_verified=false`；这属于冻结历史证据对照，不是重新运行视觉模型后的逐字节复现。视角不符及新点集须补提取，不能继承父证据。

## 预算、同分与解释

每场景两组同为最多600条：按float64分数降序；精确同分时已有原生别名优先，再按几何SHA256、类别编号升序。账本记录预算前后类别成员、独立点集、原生别名和原生点集覆盖，以及原生被挤出的数量。R1在预算前包含R0，不保证预算后仍包含R0。

R0/R1共同成员分数必须完全相同。比较只检验该冻结几何与证据下扩类的效果，不声称改善完整系统或已经解决同类竞争。R2再固定R1成员学习分数；R3/R4尚待单独设计与验证。训练内部五折按主场景分组，但冻结上游曾接触训练池，因此不是严格整系统折外；55个开发验证亦非盲测。
