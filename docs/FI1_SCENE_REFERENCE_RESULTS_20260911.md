## 1. 当前完成度

**下游训练/留出标签参照池已实现，并通过固定小样本验证。** 已生成完整五折、十份分区引用；第0折实际生成80场景训练侧标签和20场景留出侧标签，以及两份分开的数据包。当前不是完整训练集，没有训练新评分器或生成生产B2。

本次只增加两个工具和一个测试文件；此前的反事实核心、特征读取器、FI1、B1、原evaluator均未改写。77项相关测试通过，其中20项为本阶段新增测试。两个warning仍是旧合成用例在common/tail类别组为空时，原evaluator的均值提示。

## 2. 为什么没有直接复制旧fold字段

official100包含100个扫描、93个主场景。审查发现旧fold把以下6组主场景的不同扫描分到不同折：

| 主场景 | 旧fold分布 |
|---|---|
| scene0038 | 00→2，02→0 |
| scene0317 | 00→2，01→0 |
| scene0541 | 00→3，02→1 |
| scene0587 | 00→0，03→1 |
| scene0673 | 04→2，05→0 |
| scene0692 | 00→3，01→2，03→4 |

因此新下游划分以 `sceneXXXX` 为组，同一主场景的所有扫描只能进入同一折。复用仓库已有的确定性分组函数，种子固定为 `fi1-margin-main-scene-v1`，只使用场景名称，不使用GT、类别频率、AP或正例数选划分。结果五个留出折各20个扫描，每折拟合侧80个扫描。

这没有重写旧B1或旧上游模型的fold。新数据包区分：

- `legacy_fold_index`：原证据/上游产物的来源fold；
- `split_fold_index`：该扫描在新主场景分组中的fold；
- `outer_fold_index`：当前训练/评估任务留出的fold；
- `partition_role`：当前记录属于fit或heldout。

这些字段属于身份元数据，不作为评分特征。比如既有成员600/647的来源fold为4，新分组fold为2；它们可用于outer fold 0的fit侧，但不能因此改写历史上游为新OOF。

## 3. 新实现

### `tools/fi1_scene_reference.py prepare`

读取已绑定历史审计的B1和population元数据，为五折分别落盘fit/heldout引用。划分与落盘过程不打开GT cache内容或AP数组；历史summary/audit只用于输入身份绑定，不用其类别/AP统计选择划分。

每份引用包括：本分区B1预测、几何身份表、明确场景集合、允许读取的cache及哈希、完整类别词表、固定动作请求和内容标识。B1全局prediction_id和每场景原列顺序保持不变；不能在分区后重新编号。

每个分区的 `reference_id` 绑定自己的成员、几何、词表和GT cache哈希。对侧GT/预测数值不进入这一身份。全局split仅由固定场景名称和规则定义。

### `tools/fi1_scene_reference.py evaluate`

一次只运行一个显式role。先验证role和场景集合，再读取该分区cache；把heldout引用当fit使用会在读取GT前拒绝。每个候选继续使用上一批修复的三种明确动作与原evaluator，保留该分区所有场景的同类排序。

fit标签只相对于该折80个训练场景计算；heldout标签只相对于20个留出场景计算，标记 `evaluation_only`。不能先计算完整100场景delta，再按样本fold切表，那样标签仍含留出信息。

若一个类别在候选所在扫描没有GT，但在本分区其他扫描存在GT，仍保留其FP作用；若该类在整个本分区都无GT，AP目标保留null。不得从完整100场景借用GT补出训练标签，也不得把未定义目标强制变成0。

### `tools/build_fi1_scene_margin_dataset.py`

只接受同一split、outer fold、role和reference_id的分区标签，拒绝旧局部AP、完整100场景开发标签、跨fold标签或错误动作分数。显式校验训练/留出用途。

复用此前修复的视觉白名单与实际空间重叠B1分数，按 `identity/features/labels` 分开保存；将旧fold用于证据身份核对，将新split fold另存。GT标签不会被复制成特征。

`label_reference_isolated=true`仅表示下游标签参照范围已隔离；所有当前小样本包仍为 `training_ready=false`、`whole_system_oof=false`。

## 5. 不能外推的结论

本次证明的是：**固定FI1/B1和候选输入后，直接用于生成下游标签的GT与候选排序参照不会跨训练/留出边界。** 历史FI1、B1分数或细化选择可能使用过与新划分不同的监督数据，因此不能据此宣称整系统严格OOF。

当前没有拟合头、阈值选择或内层调参。未来如需内层验证，必须为内层fit/calibration分别建立参照并重算标签，不能先在outer-fit全池生成标签后再切内层训练/验证，更不能用outer-heldout选择方法。

单候选贡献依赖候选分数与参照集合；不能跨池直接拼接同一目标，也不能将delta相加当作联合收益。未来五折预测若汇总到official100，应合并各折留出预测后统一评测，而不是平均分折AP冒充总体AP。

3. 小规模代表性训练数据验收后，才实现并训练最小评分器；模型选择若需要内层划分，先建立对应标签参照。
