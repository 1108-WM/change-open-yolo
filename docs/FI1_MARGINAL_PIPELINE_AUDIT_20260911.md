## 3. 阻止当前标签用于训练的问题

### 3.1 自写局部 AP 有确定的数学错误

位置：`fi1_marginal_contribution_core.py:200–238`。

- 对一个满分正确预测，`local_ap` 输出 **-1.0**，原 evaluator 输出 **1.0**。
- 卷积积分展开符号反了；这不是 ScanNet evaluator 的异常定义。
- 未匹配 GT 被写成分数负无穷的伪 FP，没有作为 `hard_false_negatives` 纳入召回分母。
- 同一 GT 的更高分重复预测没有更新正确预测分数，缺少 evaluator 的 max/min 处理。
- 还遗漏忽略区域和部分 GT/预测过滤。

`build_fi1_marginal_increment_diagnostic.py:72` 只从预测交集中收集 GT，完全没有相交的 GT 被遗漏。此前 54033 个局部值缺失不能直接解读为对应场景无该类 GT。把字段改名为 `experimental_*` 没有修复算法，构建器仍会计算它。

**处理结论：自写局部 AP 及 run_v5 的正/负增量解释全部撤销，不用于训练或方法判断。**

### 3.2 简化匹配器也没有通过 evaluator parity

位置：`fi1_marginal_contribution_core.py:142–197`，`build_fi1_marginal_increment_diagnostic.py:43–63`。

- 简化实现按预测遍历，原 evaluator 按 GT 及其 `matched_pred` 遍历；移除内部 score 排序并不使两者等价。
- IoU 映射纳入未过滤的小 GT；预测小于 100 点、void、group、distance/confidence 的处理不完整。
- 合成反例：追加完全落在 void 的高分预测，原 evaluator AP50 仍为 1.0，简化实现却增加 FP 并标记 `ranking_harm`。
- `tp` 与 `matched_gt` 在实现中总是相等，因此 `positive_rank_gain` 分支不可达。
- `ranking_harm` 仅看候选是否高于所有同场景同类分数，与真实跨场景 PR 排序不等价；低于最大分也可能伤害 AP。
- 既有成员在 after 中被移到末尾，不是恢复完整 B1 原始列顺序。缺失或重复 prediction_id、跨场景 peer 未被完整拒绝；已复现跨场景 peer 被接受。
- 手写 `.6` 等阈值不应假设与 evaluator 的 `np.arange(.5,.95,.05)` 浮点值逐位相同。

**处理结论：1262/1186/15211/48930 是旧简化程序的输出计数，不再称为可靠 TP/FP/排序贡献标签。**

### 3.3 静态标签仍有不可达和回退问题

位置：`fi1_marginal_contribution_core.py:34–45,84–96`。

真实非目标候选的 target 集为空，但代码要求与 peer 共享 target 才允许 peer 进入比较。因而真实输入下 `ranking_harm=0` 是逻辑导致，不能用来判断数据没有排序伤害。缺失 target identity 时回退为 `__best_iou_only__` 又恢复了“不同同类 GT 被混为重复”的风险。

多 GT 阈值情形下，候选可能同时有新增覆盖和重复覆盖，当前互斥四标签不能表达；同一个已有成员移除后的覆盖贡献也不等于 B1 外新增候选贡献。静态几何覆盖可以重建为辅助诊断，但现有分支没有通过全面验收。

### 3.4 既有成员对照仍是重复追加，不是移除后恢复

位置：`audit_fi1_candidate_evaluator_delta.py:20–24`。

`pool` 已包含候选，after 又执行 `pool + [candidate]`。此前状态写成 before=移除该成员、after=完整 B1，与代码不符。

真实第 0 个 B1 成员重放：完整该场景 AP50=1.0，追加同一成员=0.975，移除该成员=1.0。旧产物记录的 1.0→0.975 正是**重复追加**的结果。

**处理结论：10 样本的结果只能保留为重复插入对照，不能解释为既有成员净贡献。**

### 3.5 新增候选 delta 是单场景 AP50，遗漏了跨场景误检作用

位置：`audit_fi1_new_geometry_evaluator_delta.py:12,17–21`。

`pool` 只含 `(scene,class)`，`evaluate_matches` 只传入一个场景，最终只取 IoU=0.5。直接调用 evaluator 本身是正确做法，但实际评测范围与“完整 B1 增量”描述不符。其他类别可以独立计算；**同一类别的其他场景不能从完整类别 PR 曲线中删掉**。

已固定重放一个旧样本：`scene0018_00` 的新增 geometry `2eda401f…`、class_index=5。局部该类 AP50 未定义，但完整 official100 的该类 AP50 从 **0.19575426555023973** 降到 **0.15785790627698634**，delta **-0.03789635927325338**。这是类 AP50 下降 3.7896 个百分点，不是总体 mAP 下降同样数值。

**处理结论：不能丢弃“局部无 GT”的候选作为无法监督样本。** 若该类在整个评测集合也无有效 GT，才保留全局未定义状态。20/100/70 几何批的数值可保留为固定分数下的局部 AP50 诊断，不能当作主 AP 或训练集正负比例的完整依据。

局部正 delta 也不保证总体正 delta。一次只追加一个候选，得到的是指定分数、指定参照池、指定动作的条件贡献；多个正贡献候选共同追加时不保证增量相加或仍为正。

### 3.6 数据集六个特征全部为空；fold 字段不等于 OOF

位置：`build_fi1_margin_dataset.py:10–11`。

数据实际在 `visual_row['features'][name]`，实现却读 `visual_row.get(name)`。300 行中的 Alpha、标签图、bbox、Alpha gap、最大几何重叠、几何邻居数 **6×300 个值全部是 null**；从同一份源视觉文件逐项核验，这六列原来各有 300 个非空值。不是缺少视觉资源。

当前只复制 fold 字段和计数，没有 fit/heldout 划分校验、标签/特征边界、模型训练或上游监督隔离凭据。还未提供 FI1 独立质量、真实同类重叠竞争分数、父子区域证据的完整新训练消费。`gt_used_for_features=false` 是自报字段，不是执行出来的防泄漏检查。

**处理结论：margin_dataset.json 不可用于训练。存在 fold 标签不代表已有场景隔离训练数据集。**

## 4. 候选生成和来源合同的问题

1. `max(alpha,label_map,bbox)` 混合不同尺度证据，并直接作为最终分数；这与已经确定的校准问题相同。正例少不能单独归因于 top-3 太窄，也不能据此扫描 k 直到正例够多。
2. “198 行”只验证计数，没有核对类别恰为 0–197、不重复、类别词表、scene/fold、点集和证据哈希。即使有完整类别行，也不保证所有视觉源有效。真实旧样本经本次复核确实在 B1 外，候选身份与 population 的 scene/fold 一致；但工具本身没有足够的拒绝错误输入能力。
3. `audit_fi1_new_geometry_evaluator_delta.py` 读取了 population，却没有使用它验证“新增”、类别、点集身份或缓存来源。文件哈希仅记录当前值，不等于验证权威 summary 和独立 audit。
4. 分层模式复用了 `counts` 变量，导致 `visual_complete_geometry_count=0`；实查 70 个几何均有完整 198 类行。这是统计代码错误。
5. 配额内依旧按 scene/key 取前若干，不是均匀场景采样。第 4 折原本没有 `refined_union`，不能通过重复样本“补齐”。
6. 710 个 B1 外几何中，688 个是 `temporary_refined`、22 个为 `refined_union`。其中有完整198类行的320个为300个临时细化、20个历史接受细化。临时细化包含未通过旧筛选的候选，不能统称生产 FI1 已接受结果。
7. 本轮后半段集中在新 refined 候选，尚未完成最初优先项——既有 union/track 重评分的边际贡献目标与新旧分数可比性。
8. 多数新入口未保存代码版本、可靠审计绑定、完整 before/after 数组及执行合同；字典联表会覆盖重复 ID；部分输出可覆盖，历史命令曾用删除重跑。今后采用新目录和失败标记，保留本轮产物追溯。

## 7. 修复顺序

1. **先固定实验动作。** 既有成员使用 `B1\{p}`→原顺序 B1；真正新几何使用 B1→B1+p；改分使用固定同一成员集。每次核验身份、数量、类别、mask、分数和顺序差异，不混称追加。
2. **用原 evaluator 建立小规模可靠参照。** 对同一类别保留完整评测场景池，直接读取 evaluator 的严格阈值、忽略和 PR 规则，保存AP50、0.50–0.90主AP及数组；无局部GT的候选仍进入全局FP分析。既有静态标签只作辅助，不自行再造AP公式。
3. **修复特征提取和校验。** 从真实 `features` 联表，分别保存推理特征、GT标签和身份元数据；核验非空率、几何点集、完整类别、同类真实重叠和竞争分数。先用固定小样本做遗漏GT、void、小实例、零分平局、重复ID、不同同类实例、重复追加等反例测试。
4. **再冻结训练参照池与场景划分。** 全 official100 反事实只用于开发诊断；用于拟合的标签不能借用外层留出场景的GT/排序结果。下游按场景隔离；冻结历史上游仍只能称冻结管线开发诊断，不能自动称整系统严格OOF，也不自动重训第一点。
5. **验收后再扩样本、训练。** 将既有 union/track 的排序问题与新 refined 的类别恢复分别评估。候选范围、分数动作和采样先定，不依据已看到的正例数持续扩top-k。Qwen暂不扩展。官方100之外的数据不用于本轮调参。

这是修复计划；本轮完成的是审计、反例重放和状态纠正，没有把上述未完成项写成已修复。
