# DM-SMS-1 第二创新点：属性证据输出合同

本合同用于后续冻结的多模态模型输出，不代表当前已经运行模型。

每个 `task_id` 必须对应一个固定 geometry 和最多三个已登记视角。模型输出只允许包含：

- 外观；
- 材质；
- 形状与结构；
- 功能线索；
- 空间关系；
- 跨视角一致性；
- 缺失或不清楚的证据。

每个属性必须记录观察文字、支持视角编号、0 到 1 的证据把握度和反证内容。属性提取阶段不允许输出类别名称、类别编号、候选类别、选中类别或新的排序分数。

如果输出缺少字段、引用不存在的视角、把握度不在 `[0,1]`、泄漏该 geometry 的候选类别名称，或者出现候选/几何/分数改动字段，审计必须失败，不能进入类别仲裁。不能直接禁止全部 198 个类别字符串，因为其中 `light` 等词也可能是合法的颜色或物理属性描述。

视角输入固定为一至三张双栏合成图：左侧是完整场景红框，右侧是同一视角的局部裁剪。提示词必须按该任务实际存在的视角数量生成，只允许引用从 `0` 开始的连续编号。只有当原编号在当前任务中不可能、且全部减一后恰好合法时才允许确定性减一；仅出现 `1` 等同时可能属于零起始和一起始的编号时不得擅自移动。

属性结果必须是**一个完整的顶层 JSON 对象**，所有视角的证据合并在这个对象中。数组、多个对象、截断对象、对象后附解释文字都不合法；解析器不得从数组或残缺文本中抽取局部对象。JSON 语法错误、输出数组、字段缺失或非法视角编号只允许固定重写一次，类别词泄漏不得通过重写绕过。原始输出、重写输出、失败阶段和重写类型都必须保存在账本中。

类别词检查必须区分目标猜测和环境描述：`spatial_context` 中的“在桌子上”“位于柜台上方”等只描述周围关系，不据此判定目标类别泄漏；属性字段中“part of a chair”“white wall with a power outlet”等部件或局部关系也不判为目标类别；但“chair with wheels”“this object is a desk”“power outlet suggests...”等句式明确指向红框目标，必须拒绝。`shape_structure` 中的 `seat/cushion` 等明确部件词只记警告。若外观、材质、功能线索或跨视角一致性明确把目标说成有限候选以外的类别，则记录 `candidate_set_insufficient_or_unclear=true`，不新增候选，并安全保持冻结原类别。

由于项目冻结类别词表为英文，属性证据文字统一要求使用简短英文；若模型输出中文类别词，英文词表无法进行确定性审计。因此出现中文字符视为输出结构不合格，只允许固定重写一次，仍不合格则安全回退。
