# 下一步：T整区补点固定规则验证

## 1. 决策与问题

采纳“T补点单独研究、联合输出为主、方向/竞争两个固定规则对照”。不将N补点失败解释为N没有改进空间，也不将其他query自动视作其他真实实例。区域query均值的排序能力不等于动作安全性。

本项只回答：在未参与这两条规则开发的物理场景上，固定T整区补点能否增加完整原NT的候选价值，并避免明显破坏T父？额外的竞争条件是否提供真实风险收益改善？

研究输出：`原N + 原T + T补点生成的备选候选`。原父全部保留。即使原N点集不动，新增候选仍可能影响后续排序/K800，本项不声称最终AP或生产安全。

## 3. 冻结的两个规则

使用局部编辑诊断的原定义，整区指原成员区域内满足`visible_groups >= 2`的可编辑部分，不是把不可见点也补进来。

|规则|条件|
|---|---|
|A：方向规则，预先指定主规则|父外整区的父query平均概率`q_mean >= 0.5`|
|B：竞争对照|A成立，并且`q_mean - competitor_mean >= 0.1`|

竞争query继续定义为当前编辑块内、除父query外平均概率最大的query。它可能重复表示同一个物体，故B检验的是“query分数排他条件”，不能称为已知实例排他性。

保持冻结Mask3D权重和正确XYZ接口、原head和原点映射、原父完整场景soft-IoU top1匹配及稳定ID平局处理、原0.15m halo、最多六帧、成员区域、邻居上限与连通规则、原可见性和min100资格。

不输入当前A/B学习修复器的输出，不训练新模型，不改变query选择，不添加query embedding或不确定性输入，不加入新区域切分，不加块尺寸阈值，不按query歧义或GT稳定性另外筛父。不将多帧common>=2增加为硬门；继续保存缺失/支持/冲突字段作诊断。若某个必要输入完全缺失，按预先约定的资产失败口径记录，不能事后悄悄换场景。

## 4. 执行输出必须固定

每个原T父、每条规则分别收集全部合格父外整区，取这些点集的union，然后与原父取并集。每个T父每臂最多生成一个联合候选；无增补则保持原父且不追加重复候选。精确点集去重并记录别名，不能把重复副本算新增供给。

A与B是两个独立实验池，不把它们同时加入同一个池挑好结果。单块候选只作后置诊断，不参与主要执行池，不用GT选择保留哪块。必须核查：B入选块集合是A子集，但B的实例IoU不必高于A。

原N与原T均不得覆盖或删改。按冻结原父名单的`source=track`确定提案来源；去重父如具有N/T双来源，记录双来源别名，沿用原T父身份生成备选，不因GT或结果改变资格。它不会修改原N点集。严格报告双来源数与收益，避免声称新增候选必然与N无关。

允许编辑区域既有N/T成员支持，也允许完整原NT均未覆盖的区域。不能只研究把原N点搬给T，否则会漏掉现有关键补回类型。

可优先检查原fit96中未进入上述诊断的剩余场景，但这些可能已用于前序模型训练或开发，必须登记。结论准确称为“对本轮规则开发物理隔离的内部验证”，若冻结先验或上游已见过这些数据，不能称全项目盲测。类别/监督之外的信息也可能造成开发暴露，要据可追溯记录说明。

在元数据暴露审计完成后，用固定种子`20261014`与物理scene ID的SHA256排序选前24个；若保留历史90/新110分层，预先固定各12个及不足时的处理，不按结果补齐。不能在看到本批结果后追加场景直到获得成功。若没有足够合法场景，先报告真实可用数量并冻结有限评估范围，不挪用最终holdout。

## 7. 主要指标与解释

### 新增候选价值

主要口径为固定union候选加入完整原NT后的每目标最佳IoU变化，`delta >= .02`按(scene,GT)去重。完整目标分母包括没有生成动作的场景，不能只统计有提案场景。

同时核查每项收益是否对应其父目标、编辑是否净改善、补点中目标/邻物/未知各占多少。报告严格见证：稳定同父目标、净改善、增补点目标比例>=.9且已知标注比例>=.9。非同父目标收益、身份不稳定父收益、含大量未知的收益可以保留在原始池表，但不得混称确定正确的父修复。

主要继续研究证据建议至少2个不同物理场景出现严格同父union收益>=.02；单个场景不够，多份父/提案改善同一目标也不能当多个。另报跨>.50/.75/.90/.95覆盖、连续池增量和总体平均；>=.02收益与跨档位覆盖不是同一件事，不要求所有有效改善都跨档位。

### 风险与覆盖

报告所有T、稳定T、身份不稳定T、所有好T及实际编辑好T的分母。好T定义沿用父IoU>=.90。报告全部稳定父退化、最坏损害、好T损失>.02与>.10，以及按物理场景分布。

本项继续研究的保护目标：没有好T损失>.02，并且不存在稳定T损失>.10；任何这类失败不能靠平均收益掩盖。这是预先研究验收标准，不保证部署安全。若实际编辑好T为0或很少，明确报告保护证据不足；不得因为大量N未被编辑而宣称好父保护已验证，也不得事后按GT挑好T加入验证。

补点已知正确率、未知标注点、身份不稳定父编辑量分别列出；不能把未知当正确或当错误。建议已知补点正确率>=.9作为必要保护指标，同时给出场景差异。严格同父收益不能替代对未知父输出的安全判断；大量未决编辑存在时，结论最多是受限支持，不能写全范围安全通过。

### 竞争条件的真实作用

固定报告A/B所有上述指标与逐父配对：B去掉哪些错误，同时损失哪些正确补点和池收益；原始数量、条件比例和无动作覆盖同时报告。

- A有效而B丢失全部池价值：竞争条件没有兑现有效供给，不能把“更少动作”当成功。
- B减少错误且保留或增加跨场景严格池价值：支持进一步研究竞争条件，但不是证明query与真实实例一一对应。
- B安全与收益相互取舍：如实报告，不事后挑选赢家或新阈值。A是预先主规则，B是单一机制对照；任何据本批结果形成的新规则需要新的验证。
- A/B都无多场景严格收益或明显伤害：停止本项固定规则的扩展，不在这批数据上继续扫阈值。该有限样本负结果不等于不存在任何T补点方法；后续若要继续，应提出新的区域供给或身份机制假设。
