成员哈希明确序列化为原seed加 `scene|geometry_key|class_index`；所有动作的ID、原分数、阈值、标签和不可用原因在任何新AP之前整体写入 `actions.json` 并绑定。置零标签不会直接成为部署筛选规则。缺层不补；无法合法换入的动作记录不可用。

## 实现与评测核验

新文件 `tools/fi1_r3b_delta_diagnostic_core.py` 与 `tools/run_fi1_r3b_delta_diagnostic.py` 独立于运行链。复用 `fi1_gain_attribution_core.py` 的点集直方图/稀疏关联，通过原评测器的稠密掩码关联函数核验。

为避免导入Torch/CUDA共享库占用2 GiB虚拟地址空间，读取绑定后的原源码AST，执行原样的 `evaluate_matches`、`compute_averages`、`make_pred_info`、`assign_instances_for_scan` 及原GT实例函数；不改AP方程、匹配、忽略规则或阈值。类别/索引来自原constants。这里调用的是原函数内核，非重新运行完整 `evaluate()` 包装器；历史全折数组重放和原稠密关联是验证依据。合成测试另与正常导入的原评测器核对数组，防止AST装载/全局配置偏差。

20场景均从已审计点集与训练GT重建稀疏关联，并与原稠密关联缓存（仅去掉分析注释）逐字段一致；每场景替换成新关联但不做动作时，全40扫描AP应与基线一致。每折第1个预选场景再运行原稠密关联：基线及每种可用动作的第1个，固定选择不看ΔAP。单次稠密掩码上限400 MiB；若超限记录失败并停止，不以跳过校验伪装通过。

原整体评价指标只报告有类别AP/AP50/AP25，0—1存储，文字差值换算为百分点。NaN保持未定义、不变为零；反事实有效类别分母必须与基线一致。记录唯一几何、主场景以及重叠GT ID（有重叠不等于成功匹配）。单动作是条件收益，不是候选固有标签；下游折外不等于上游全系统折外。
