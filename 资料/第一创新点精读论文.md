## 0. 用途、边界与当前结论

本文件把第一创新点相关论文压缩成“新对话可直接使用”的研究结论：每组论文只保留研究问题、最重要的创新、证据、可借鉴点，以及对当前代码的直接启发。详细原文、公式推导、图表和补充材料已在此前阅读中核对；这里不重复论文全文。

本次阅读没有修改实现代码、没有重跑 AP、没有读取新的真实标签，也没有停止或干预 DM-SMS-1。论文中的数值属于各自论文的评测合同，不能直接当作本项目结果。

当前第一创新点：

```text
native 候选保持不变
  + 多视图轨迹候选
  -> exact geometry 折叠
  -> q 与 P(keep) 的分数抑制
  -> pair-union threshold-cross 候选 append-only
```

当前 val312 类别无关结果（AP / AP50 / AP25）：

```text
native                  50.606943 / 67.975380 / 77.977661
轨迹伤害抑制            52.200359 / 70.182853 / 79.642081
再加 pair-union         52.396219 / 70.299971 / 79.734125
```

相对 native 总提升约 `+1.789276 AP`；pair-union 额外仅约 `+0.195860 AP`。因此轨迹候选确有价值，但 union 的表达和排序仍明显不足。

## 1. 论文结论总览：先记住这五句话

1. **多视图候选能补召回，但轨迹并集不是最终掩码。** 所有强方法都会在合并后重新做成员细化、投影一致性检查或点级过滤。
2. **重复抑制是候选集合关系问题。** exact duplicate、near duplicate、包含、互补和冲突不能用一个 IoU 阈值或一个固定幂映射统一处理。
3. **候选质量必须直接对应 AP 排序。** 分类分数、轨迹质量、组件代表概率和 union 分数不是天然同义；不同来源直接比较会损害 AP。
4. **唯一 winner 标签不等于候选质量标签。** 第二个候选可能是重复，也可能是互补补全；把所有非 winner 设为 0 会误伤互补学习。
5. **增益稀疏时要使用连续收益目标。** 当前 threshold-cross 正例约 50 个，二元标签过稀，应建模多阈值几何质量和相对已保留集合的边际收益。

## 2. 多视图候选生成与轨迹接入

### 2.1 Details Matter

**核心创新：** 用二维去重、跨帧轨迹、多视图点过滤、迭代合并和包含删除，把碎片化二维掩码变成三维候选；合并后再次细化，而不是直接接受并集。其类别无关 AP 把候选置信度固定为 `1.0`，主要评价掩码集合，不评价跨来源排序。

**可借鉴：** 轨迹、合并、包含处理必须分阶段；类别无关 AP 与排序 AP 要分开报告。

**对当前代码的启发：** 当前 pair-union 是裸点集并集，缺少“并后成员细化”和 containment 处理；不能把论文的类别无关结果当成当前分数合同的验证。

### 2.2 OpenTrack3D

**核心创新：** 轨迹关联同时使用视觉相似度和体素 IoU：

```text
s = α·cos(视觉特征) + (1-α)·IoU_voxel
```

消融显示去掉任一项都会下降；轨迹长度排序和高 IoU 合并只是启发式，不能当作严格掩码质量。

**可借鉴：** 视角变化需要外观证据，空间相邻需要几何证据，两者联合比单项可靠。

**对当前代码的启发：** `q` 应拆成视觉、空间、可见率、深度一致性等可解释分量；`P(keep)` 不应被解释成绝对安全概率。

### 2.3 Any3DIS

**核心创新：** 枢轴视角同时看自身可见点和邻域可见性；先生成高召回三维候选，再通过多视图目标函数优化超点成员，而非直接使用所有提升点。论文消融中多视图成员优化带来最大收益（约从 `20.8` 提到 `22.2 AP`）。

**可借鉴：** “候选生成”和“候选内部成员选择”必须分离。

**对当前代码的启发：** union 至少应把 `track-only / native-only / shared` 成员分开评估，按二维支持率、深度误差、连通性和边界状态保留或删除。

### 2.4 MaskClustering

**核心创新：** 用共同观察视角中的掩码共识构图：

```text
c(i,j)=共同支持视角数 / 共同观察视角数
```

高证据关系先合并，低证据关系后处理；同时过滤多视角反复欠分割的掩码。

**可借鉴：** 关系证据应按观察数量归一化，并采用渐进式聚类，避免弱边串联。

**对当前代码的启发：** `P(keep)` 目前只描述组件内 winner，缺少候选对之间的共同视角支持、观察数和欠分割风险。

### 2.5 MV3DIS、Open3DIS、OVIR-3D、SAM3D、SAI3D

这些论文共同形成一条清晰路线：

- **MV3DIS：** 用三维粗区域作为多视图共同参考，并加入连续深度一致性权重；边界点不应只用二值 IoU 判断。
- **Open3DIS：** 二维候选和三维候选先补召回，再统一关系去重；两来源如何融合仍是开放问题。
- **OVIR-3D：** 点级支持率和非对称包含关系可区分完整候选、局部候选和 near duplicate。
- **SAM3D：** 相邻帧双向合并简单但易产生错误累积，不能作为全局关系模型。
- **SAI3D：** 超点亲和应由多视角加权，区域生长应比较候选与“整个已生长区域”，并逐步降低阈值；不能只看一对父候选。

**对当前代码的共同启发：** 需要把 `exact duplicate / near duplicate / containment / complementary / conflict / uncertain` 明确分型，并为每类关系定义不同动作。

## 3. 候选聚合、内部细化和原生底座

### 3.1 3D-MPA、PointGroup、HAIS、SoftGroup、ISBNet

| 论文 | 一针见血的创新 | 对当前第一点的直接启发 |
|---|---|---|
| 3D-MPA | 候选关系图和几何/嵌入聚合明显优于固定 NMS；AP50 消融约 `47.5→59.1`。 | 关系特征应直接参与最终排序和聚合，不应只用于生成伤害标签。 |
| PointGroup | 用连续 IoU 质量训练 ScoreNet，而非复用类别概率；质量目标在 `0.25~0.75` 间线性变化。 | 为 native、track、union 建立同一几何质量标尺。 |
| HAIS | 聚合后做候选内部逐点前景/背景细化，并用细化后 IoU 监督质量。 | union 不能直接输出原始并集；需成员级 refinement 和质量重估。 |
| SoftGroup | 先高召回地产生含背景候选，再做候选级类别、掩码和质量预测。 | pair-union 的定位合理，但当前缺少“高召回后细化”阶段。 |
| ISBNet | 训练允许一对多召回，推理仍统一去重；最终分数为 `sqrt(class×mask-IoU)`。 | 召回扩展与最终去重可以分阶段设计，不能因为 append-only 就放弃关系重排。 |

### 3.2 Mask3D 与 OpenMask3D

**Mask3D：** 原生查询已通过匈牙利一对一匹配、自注意力和 DBSCAN 处理查询竞争与空间碎片；增加查询数收益很小，说明 native 已有明显数量/重复天花板。新增轨迹应专注 native 未覆盖的多视图互补区域，不要重复发明 native 的查询去重。

**OpenMask3D：** 对候选按可见点数选代表视角，1/5/10 视角结果显示代表视角比盲目增加视角更重要。

**直接启发：** 轨迹质量 `q` 应保留视角选择和可见率统计，不能折叠成一个无法解释的标量。

## 4. 重复抑制和候选关系

### 4.1 Soft-NMS、Matrix NMS、Learning NMS、Relation Networks、DETR

- **Soft-NMS：** 按 IoU 连续降分而非硬删除，减少阈值跳变；但无法理解包含和互补。
- **Matrix NMS：** 用全体 IoU 矩阵一次性计算压制关系，比逐候选贪心更接近集合级排序；仍不理解多视图互补。
- **Learning NMS / GossipNet：** 用关系网络学习“一候选对应一个 GT”的集合决策；说明重复不是单候选属性，但唯一匹配标签会把有价值的第二候选误作负例。
- **Relation Networks：** 几何和外观关系共同决定候选权重，固定 NMS 不是唯一方案。
- **DETR：** 用匈牙利一对一匹配把去重纳入训练；不适合直接表达“第二候选作为互补补全仍有正收益”。

**对当前代码的结论：** 当前固定 `1-(1-p)^3` 只是概率映射，不是关系型 NMS；它没有使用候选间的 IoU、包含、互补、来源和分数顺序。后续应采用关系级重排序，而不是继续调幂指数。

## 5. 质量估计和 AP 排序

### 5.1 IoU-Net、Mask Scoring R-CNN

两者共同证明分类分数不等于几何质量，Mask Scoring R-CNN 使用：

```text
最终分数 = 类别分数 × 预测 mask-IoU
```

但不同来源的分支即便都预测 IoU，也需要校准后才能比较。

### 5.2 GFL、QFL、VarifocalNet、Rank & Sort Loss

这些方法把连续 IoU 作为质量标签，直接优化高质量正例的排序。QFL 的核心是让分类位置输出连续质量，而不是二元 0/1；Rank & Sort 进一步同时约束“正例高于负例”和“高 IoU 正例高于低 IoU 正例”。

**对当前代码的结论：** `P(keep)` 实际是“组件内唯一代表概率”，不是候选安全概率；当前 `duplicate_valid→0` 的标签无法学习互补候选质量。应至少拆成：

```text
独立候选几何质量 Q_i
重复/冲突风险 R_i
相对已保留集合的边际收益 ΔQ_i
```

## 6. 对当前实现的综合审查判断

代码审查已确认：exact geometry 折叠、轨迹抑制公式、pair-union 点集和 SHA-256、prior correction、append-only、OOF 场景隔离及 native 回退没有发现使结果失效的确定性错误。当前问题主要是方法语义和建模能力：

1. `P(keep)` 标签把唯一选择与候选质量混在一起；
2. native、track、union 分数来源不同、未证明可比；
3. union 只做裸并集，没有成员细化和并后质量重估；
4. 关系模型只用于伤害抑制，没有进入最终全候选排序；
5. threshold-cross 正例稀疏，无法稳定支撑复杂二分类器；
6. near duplicate、包含和互补关系尚未统一建模。

因此，目前不能说“代码写错导致 AP 小”，更准确的是“冻结实现合同基本正确，但第一点仍是一个不完整的候选关系与质量建模方案”。

## 7. 最推荐的代码修改顺序（只允许新预注册分支）

不得在 val312 调参；不得停止 DM-SMS-1。所有修改在 NCS-train100 新建独立、可回退的预注册分支，并一次性迁移评测。

### 优先级 1：统一三来源质量分数

使用同一多阈值几何质量目标（例如 `IoU@0.50:0.95` 的平均或分桶质量），分别校准 native、track、union；先画可靠性曲线和分数分布，再决定融合公式。不能继续假设 `q`、`P(keep)`、`P(threshold_cross)` 数值同义。

### 优先级 2：把关系级重排序放到最终候选集合

先计算候选对关系：IoU、非对称包含率、共同视角支持、来源、分数差、中心/连通性和互补性。按关系类型采取：

```text
exact duplicate → 折叠
near duplicate  → 连续降分
containment      → 保留完整者或降局部者
complementary    → 进入 union 候选
conflict         → native 安全回退
uncertain        → 保守保持
```

### 优先级 3：pair-union 成员细化

把 union 点分成 `track-only / native-only / shared`，逐点或逐超点预测保留概率；输入应包含多视图支持率、投影 IoU、深度一致性、连通性、边界状态及父候选证据。细化后重新计算几何质量与分数。

### 优先级 4：从二元 threshold-cross 改为连续收益

标签不再只问“是否跨过一个阈值”，而是记录候选自身多阈值质量、加入当前高分集合前后的 AP 代理增益或 IoU 增益。若仍保留二元标签，必须报告正例数、PR-AUC、校准误差和五折稳定性。

### 优先级 5：分数和结果审计

每个分支必须保存 AP/AP50/AP25、五折方向、head/common/tail、proposal recall、exact/near duplicate 率、native/track/union 分来源召回、新增候选改善/伤害/中性数、union 成员删除率和各来源可靠性曲线。

## 8. 明确不建议做的事

- 不在 val312 上临时调 `P(keep)` 幂指数、阈值或 union 分数；
- 不把所有非 winner 候选继续标为质量 0 后训练更复杂的分类器；
- 不把 track 长度、可见帧数或单个 `q` 直接当作 AP 排序分数；
- 不用一次性大并集替代候选成员细化；
- 不因 pair-union 只有约 `0.20 AP` 额外收益就停止 DM-SMS-1 或否定整个第一点。

## 9. 最终可执行判断

当前第一点可以作为**有效的冻结基线**：实现合同基本正确，轨迹伤害抑制带来了真实增益；但它还不是完整的论文级候选融合方案。最可能带来可靠提升的不是继续调一个阈值，而是：

```text
统一质量标尺
→ 关系级重排序
→ union 成员细化
→ 连续边际收益学习
```

新对话只需先阅读本文件，再阅读 `资料/第一创新点代码审查结果.md`，即可直接进入代码设计和 NCS-train100 预注册工作。
