刚才解决这类问题的关键步骤是：清理远程服务器上的 Codex 和 VS Code Server，再重新连接。注意这次不要关闭本机的 cc-switch。

请按下面顺序操作。

先关闭所有 VS Code 窗口，然后在本机普通终端执行：

ssh FenGe

进入远程服务器后，先查看：

pgrep -af '[.]vscode-server|[o]penai.chatgpt|[c]odex'

然后只清理远程 Codex 和远程 VS Code Server：

pkill -TERM -f '[o]penai.chatgpt-.*/bin/.*/codex'
pkill -TERM -f '[.]vscode-server'
sleep 5

再次确认：

pgrep -af '[.]vscode-server|[o]penai.chatgpt|[c]odex'

如果仍有残留，再执行：

pkill -KILL -f '[o]penai.chatgpt-.*/bin/.*/codex'
pkill -KILL -f '[.]vscode-server'

确认没有输出后：

exit



然后确认本机 cc-switch 仍然运行：

pgrep -af cc-switch
ss -ltnp | grep ':15721'
curl -i --max-time 5 http://127.0.0.1:15721/v1/models

必须能看到端口监听和 HTTP 响应。

之后重新打开 VS Code，连接 FenGe。远程终端再确认：

ss -lnt | grep ':15721'
curl -i --max-time 10 http://127.0.0.1:15721/v1/models

最后再打开那条 Codex 对话。
需要注意：
- 不要执行 pkill -f code，它过于宽泛；
- 不要杀本机 cc-switch；
- 不要删除 ~/.codex 或 VS Code 的 globalStorage；
- RemoteForward 15721 的连接必须在 cc-switch 已启动后重新建立。
如果清理远程 VS Code Server 后仍然出现该提示，那么就不要继续反复重启；直接在远程 Codex 中新建一条对话测试：
- 新对话正常：原对话的 owner 状态卡住；
- 新对话也失败：再检查远程 Codex app-server 或供应商接口。
