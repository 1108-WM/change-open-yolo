# 第一创新点代码审查结果

更新日期：2026-08-22

## 0. 审查范围和结论摘要

本文件记录第一创新点相关代码和合同的只读审查结果。审查没有修改代码，没有重跑 AP，没有读取新的真实标签，也没有停止或干预 DM-SMS-1。

第一创新点名称：**风险感知的多视图轨迹候选安全接入与关系几何补全**。

总体结论：

- 没有发现会使当前 AP 结果无效的确定性代码错误；
- exact geometry 折叠、轨迹分数抑制、pair-union 点集构造、prior correction、append-only 和 native 回退均有代码合同支撑；
- 当前主要问题是方法定义和分数语义不严谨，不是简单的缓存、join、点集或 evaluator bug；
- val312 的总提升约 `+1.789276 AP` 是真实提升；pair-union 的额外提升只有约 `+0.195860 AP`，更可能是结构表达能力不足。

## 1. 当前冻结结果

```text
native                  50.606943 / 67.975380 / 77.977661
轨迹伤害抑制            52.200359 / 70.182853 / 79.642081
再加 pair-union         52.396219 / 70.299971 / 79.734125
```

当前分数合同：

```text
track_score = full_quality_q * (1 - (1 - P(keep))**3)
base_quality = min(track q, native exact-group median q)
append_score = base_quality * (1 - (1 - P(threshold_cross))**3)
```

## 3. 已确认正确的实现合同

### 3.1 native 保护

native 候选没有被轨迹模型删除。轨迹和 union 都是 append-only 或分数抑制，不会破坏 native 回退。

### 3.2 点集和 geometry hash

pair-union 使用冻结点集，检查点数和 SHA-256；跨来源 geometry 折叠重新计算 geometry hash。没有发现把候选编号误当作 geometry 唯一键的情况。

### 3.3 prior correction

pair-union 模型训练使用 50/50 类别平衡权重，推理前恢复 official100 组件平衡自然正例率；测试 `tests/test_run_frozen_safety60_champion_pair_union_ap.py` 覆盖缺少 natural prior 时拒绝运行的路径。

### 3.4 append-only

pair-union 只作为追加候选进入账本，不替换 native/track。即使 union 质量较低，也不会导致原有候选消失。

### 3.5 OOF 和场景隔离

训练和 OOF 过程使用场景隔离五折，推理计划携带 split manifest 和来源摘要。未发现把 val312 结果回灌到训练或阈值选择的代码路径。

## 4. 未发现确定性 bug，但必须修正的定义问题

### 4.1 `P(keep)` 不是严格的安全保留概率

训练标签对每个 GT 只选择一个 unique winner。组件内其他高 IoU 候选被标记为 `duplicate_valid`，质量目标置 0。因此当前模型实际学习的是：

```text
组件内唯一代表概率
```

它没有直接学习：

- 候选自身的连续几何质量；
- 候选相对 native 的互补收益；
- 候选加入当前集合后的边际 AP 贡献；
- union 父候选的成员污染风险。

建议未来重命名字段或新增独立质量目标，不能继续把该概率不加限定地解释为“保留无害概率”。

### 4.2 固定三次幂不是候选关系模型

固定映射：

```text
1 - (1 - p)**3
```

具有单调性和分数上界保护，但它只看单个候选概率，不看：

- 与更高分候选的交并比；
- 非对称包含率；
- 候选来源；
- 分数差和排名；
- 多视图共同支持；
- union 是否带来新的覆盖。

因此它不是严格意义的 NMS 或集合决策，只是固定校准映射。后续可参考 Matrix NMS、Relation Networks 和 Learning NMS 设计组件级关系模型，但必须新建预注册分支。

### 4.3 native、track、union 分数语义不统一

当前三类分数分别表示：

```text
native：Mask3D 原始类别概率与掩码置信度组合
track：轨迹质量 q × P(keep) 映射
union：父候选质量 × P(threshold_cross) 映射
```

数值都在类似区间，不代表随机变量相同。直接合并排序会产生来源尺度偏差。建议后续统一训练目标为多阈值 AP 相关质量或边际集合收益，并报告来源校准曲线。

### 4.4 pair-union 是裸并集

pair-union 点集构造和 hash 合同正确，但并集后没有候选内部成员重判。以下情况无法被当前结构区分：

```text
track-only 污染点
native-only 污染点
shared 稳定点
仅由连通关系带入的边界点
```

这与 HAIS、SoftGroup、Any3DIS、MV3DIS 中“先扩大召回，再细化成员”的共同设计不同，可能解释 union 对 AP/AP50 的额外收益很小。

### 4.5 threshold-cross 标签过于稀疏

只有约 50 个正例，模型 PR-AUC 约 `0.1053`、ROC-AUC 约 `0.5896`。这不是确定性实现错误，但说明二元事件定义本身信息量不足，跨场景泛化容易受少数样本影响。可在新开发分支中改用多阈值增益或连续 IoU 增益。

### 4.6 exact duplicate 正确，但 near duplicate 尚未统一

当前 exact geometry hash 折叠只处理点集完全相同的候选。近重复、包含和互补候选仍依赖训练组件和 threshold-cross 规则，没有统一动作合同。建议至少输出 pairwise relation audit：exact duplicate、near duplicate、containment、complementary、conflict、uncertain。

## 5. 为什么 train100 与 val312 的收益不同

这不是代码错误的充分证据。更可能是以下因素叠加：

1. Mask3D native 已有较强类别无关候选，存在几何上限；
2. train100 中轨迹互补关系更集中，迁移到完整 val312 后分布更分散；
3. unique winner 标签把高质量重复候选当成负例；
4. union 正例只有 50 个，模型泛化能力有限；
5. 裸并集提高召回，但边界污染限制高 IoU AP；
6. 三来源分数尺度不统一，新增候选排位不足。

## 6. 推荐的新分支，不得在当前冻结结果上直接修改

### 分支 A：统一候选质量

所有来源预测同一目标，例如：

```text
Q = mean over IoU thresholds 0.50:0.05:0.95
```

报告校准、五折、来源召回和 AP，不改 geometry。

### 分支 B：组件级关系重排序

输入候选自身质量和关系特征：IoU、包含率、来源、分数差、点数比、多视图支持、连通性。输出连续衰减或集合级重排，保留 native 回退。

### 分支 C：pair-union 成员细化

保持 union 生成条件不变，只增加点/超点级成员模型：

```text
原始 union → 成员可靠性预测 → refined union
```

### 分支 D：拆分三个目标

```text
独立几何质量
重复风险
相对 native 的互补收益
```

不能再由单个 `P(keep)` 同时承担三种语义。

## 8. 最终审查结论

当前实现可以作为冻结基线继续使用，不能据此断言“代码没有任何可改进处”。准确表述是：

```text
实现合同基本正确，结果有效；
主要风险在方法定义、标签语义、候选关系和分数可比性；
pair-union 最需要增加候选内部成员细化；
任何修改都应在 NCS-train100 新分支预注册后进行；
不得在 val312 调参，不得停止 DM-SMS-1。
```

## 9. 后续代码修改唯一准据（新对话必须以本节为准）

本节是第一创新点后续实现的唯一执行合同。`资料/第一创新点精读论文.md` 负责提供论文依据、方法解释和设计启发；其中的论文建议不是已授权的代码变更。若两个文件的措辞看起来不同，以本节为准。

### 9.1 当前开发边界

- 当前冻结实现不回退、不覆盖、不在 val312 上调参。
- 不停止、不重跑或干预 DM-SMS-1。
- 所有新代码必须建立在 `NCS-train100` 的独立预注册分支上；完成训练、五折 OOF 和审计后，才允许一次性迁移到冻结评测集。
- native geometry、原有 native 候选和安全回退必须保留；新分支不得以删除 native 或改变已有 geometry 作为主要增益来源。
- 第一阶段只做类别无关几何候选与排序，不把第二创新点的类别仲裁混入本分支。

### 9.2 唯一推荐实施顺序

#### 阶段 A：统一三来源几何质量（第一优先级）

对 native、track、union 使用同一个连续几何质量目标，例如：

```text
Q_i = mean[ 1(IoU_i >= 0.50), ..., 1(IoU_i >= 0.95) ]
```

或等价的多阈值质量分桶。分别训练/校准每个来源的质量预测，并报告可靠性曲线、来源分布和五折稳定性。禁止继续把 `q`、`P(keep)`、`P(threshold_cross)` 当作同义概率。

#### 阶段 B：候选关系审计和集合级重排序（第二优先级）

先为候选对输出关系账本，至少包含：几何 IoU、双向覆盖/包含率、点数比、来源、分数差、共同观察视角、投影支持、连通性和互补性。关系必须分为：

```text
exact duplicate / near duplicate / containment /
complementary / conflict / uncertain
```

动作合同固定为：

```text
exact duplicate → geometry 折叠
near duplicate  → 连续降分，不立即删除
containment     → 优先完整候选，保留明确互补例外
complementary   → 允许进入 union 候选
conflict        → native 安全回退
uncertain       → 保守保持，不强行合并
```

关系特征必须参与最终候选集合重排序，而不能只用于生成 `P(keep)` 伤害标签。固定 `1-(1-p)^3` 不能作为关系模型的替代品。

#### 阶段 C：pair-union 成员细化（第三优先级）

保持现有 union 生成和 append-only 安全边界作为对照，只新增成员级 refinement：

```text
原始 union
→ track-only / native-only / shared 成员分解
→ 点或超点保留概率
→ 多视图投影、深度、连通性和边界约束
→ refined union
→ 重新计算 Q 和最终分数
```

不得直接把裸点集并集当作最终掩码，也不得只用父候选分数决定所有成员去留。

#### 阶段 D：把 threshold-cross 改成连续收益目标（第四优先级）

保留现有二元 threshold-cross 作为冻结对照，但新分支优先记录：候选自身多阈值质量、加入当前高分集合前后的质量变化，以及对已覆盖区域的边际收益。只有在正例数、五折稳定性和校准质量达到预注册门槛后，才允许训练新收益模型。

### 9.3 每个新分支必须交付的审计结果

必须同时保存：

- AP、AP50、AP25；
- 五折方向，以及 head/common/tail；
- proposal recall；
- exact/near duplicate、containment、complementary 的比例；
- native/track/union 分来源召回；
- 新增候选改善、伤害、中性数量；
- union 成员保留/删除统计；
- 各来源分数分布、可靠性曲线和校准误差；
- native 回退率、低证据回退率和任何候选删除原因。

### 9.4 阶段门槛和禁止事项

在 NCS-train100 上，如果新分支不能同时说明“质量分数更可比、关系动作可解释、union 成员污染下降、五折没有单折灾难”，就不得迁移到 val312。禁止：

- 在 val312 根据 AP 选择阈值、幂指数、损失或来源权重；
- 继续把所有非 winner 候选标成质量 0 后扩大模型；
- 以 track 长度、可见帧数或单个 `q` 直接替代几何质量；
- 为了提高 AP 删除 native、改变 geometry 或破坏 append-only 回退；
- 因 pair-union 当前额外收益较小而直接否定轨迹候选或停止其他正在运行的研究任务。

**执行优先级最终写法：**

```text
先读本节
→ 在 NCS-train100 预注册阶段 A
→ 审计三来源质量是否可比
→ 再做阶段 B 关系级重排序
→ 再做阶段 C union 成员细化
→ 最后才考虑阶段 D 连续边际收益
→ 通过门槛后才允许冻结迁移评测
```
