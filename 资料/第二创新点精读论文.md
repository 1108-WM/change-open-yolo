## 1. 当前第二创新点的代码和合同基线

### 1.1 当前方法结构

当前第二创新点可以概括为：

```text
冻结 geometry node、掩码、成员关系和排序分数
→ 每个 geometry 选择最多 3 个互补视角
→ 先提取不含类别名称的属性证据
→ 只在冻结原类别与 Alpha-CLIP 类别的有限集合中进行类别证据判断
→ 对双候选执行 AB/BA 两种顺序
→ 满足双顺序支持且无强反证时才换类
→ 其他情况保持冻结原类别
```

### 1.2 当前关键文件

- `tools/build_dm_sms1_candidate_evidence_manifest.py`：建立有限候选和 AB/BA 输入账本；
- `tools/run_dm_sms1_single_scene_vlm_smoke.py`：真实 Qwen 属性、AB、BA 推理烟雾程序；
- `tools/apply_dm_sms1_semantic_arbitration.py`：读取两种顺序的 `supported`、`strong_counterevidence` 并作决定；
- `tools/audit_dm_sms1_attribute_evidence_output.py`：审计属性字段、视角、把握度、类别词泄漏和冻结字段；
- `docs/DM_SMS1_ATTRIBUTE_EVIDENCE_CONTRACT_20260818.md`：属性输出合同；
- `docs/DM_SMS1_ARBITRATION_DECISION_CONTRACT_20260818.md`：双顺序仲裁合同。

### 1.3 当前已确认的安全机制

- 严格要求单个完整顶层 JSON 对象；数组、多对象、截断内容和对象后附解释均无效；
- JSON/字段/视角编号问题最多固定重写一次；类别词泄漏不能通过重写绕过；
- 属性阶段隐藏候选名称；
- 类别阶段只允许冻结候选集合，不允许模型新增第三类别；
- 双候选必须执行 AB/BA；
- 无效证据安全回退到冻结原类别；
- 所有决定必须保持 `candidate_mutation=false`、`geometry_mutation=false`、`score_mutation=false`、`proposal_deletion=false`；
- 已完成严格独立切片：`19/20`、`95/100`、`449/497` 严格有效，497 条有效率 `90.3421%`，两轮独立审计错误数为 `0`。

### 1.4 当前已发现、但尚未修补的主要逻辑缺口

当前仲裁代码只要求：

```text
替代类别 AB/BA 双支持
+ 替代类别 AB/BA 均无强反证
→ 换类
```

它还没有要求冻结原类别在 AB/BA 两种顺序下都存在强反证。因此，更稳妥的规则应为：

```text
替代类 AB/BA 双支持
+ 替代类 AB/BA 均无强反证
+ 原类别 AB/BA 双强反证
→ 才换类
否则保持原类别
```

这不是当前运行中的临时修补建议，而是论文综合阅读后应在新合同中优先验证的结构性候选。

## 3. Antidote：反事实前提与对象幻觉的统一处理

论文：`Antidote: A Unified Framework for Mitigating LVLM Hallucinations in Counterfactual Presupposition and Object Perception`。

本地材料：

- `/tmp/antidote_2504.20468.pdf`；
- `/tmp/antidote_2504.20468.txt`；
- `/tmp/antidote_src/`：论文源文件、补充图和表；
- `/tmp/antidote_repo/`：官方公开实现的主要脚本。

### 3.1 问题定义

论文区分两类问题：

1. 普通对象感知幻觉：回答中描述图像中不存在的对象、属性或关系；
2. 反事实前提问题（CPQ）：问题本身假定了图像中不存在的对象，例如“图中的车是什么品牌”，但图中没有车。

论文认为，模型常常先接受问题中的对象前提，再执行后续问答，因此即使模型在“图中是否有车”上能回答没有，在“车是什么品牌”上仍可能编造答案。

### 3.2 数据合成流程

论文从 CC3M caption 建立候选池，然后：

1. 使用 DeepSeek-V2 重写和过滤 caption；
2. 生成实际存在对象 `O_pre`；
3. 生成场景中常共现但计划排除的对象 `O_hallu`；
4. 使用 Stable Diffusion 3 生成图像，将 `O_hallu` 放入负提示；
5. 使用 Grounding-DINO 检查存在对象和排除对象；
6. 生成 CPQ、TPQ、对象存在和图像描述问题；
7. 由基础模型生成原始回答，再加入事实提示生成自纠回答；
8. 将原始回答作为 rejected，将自纠回答作为 chosen，进行 LoRA-DPO。

论文正文明确承认：只使用 CPQ 会使模型过度谨慎，因此必须加入 TPQ 平衡真实存在对象的接受能力。

### 3.3 数据规模与训练设置

- 初始生成约 `14,000` 个 caption/对象三元组；
- Grounding-DINO 过滤约 `4,000` 个；
- 对每个目标模型再过滤约 `15%` 原回答和自纠回答过于相似的样本；
- 最终采样：`5,000 CPQ + 5,000 TPQ + 2,000` 对象存在问题 + `8,000` 图像描述问题，共 `20,000` 条；
- LoRA rank `64`；
- LoRA alpha `128`；
- DPO beta `0.1`。

### 3.4 主要指标

CP-Bench 测试集，LLaVA-1.5-7B：

| 指标 | 原模型 | Antidote |
|---|---:|---:|
| F1 | 5.7 | 78.4 |
| Accuracy | 50.5 | 84.5 |
| Precision | 60.0 | 73.1 |
| Recall | 3.0 | 73.1 |

LLaVA-1.5-13B：

| 指标 | 原模型 | Antidote |
|---|---:|---:|
| F1 | 17.3 | 83.5 |
| Accuracy | 53.8 | 84.5 |
| Precision | 82.8 | 89.5 |
| Recall | 9.6 | 78.3 |

POPE：

|---|---:|---:|

LLaVA-1.5-7B 的 CHAIR-S 从 `19.4` 降到 `9.4`，CHAIR-I 从 `6.1` 降到 `3.3`，SHR 从 `36.7` 降到 `18.1`。

### 3.6 官方实现逐文件核对

#### `data_pipeline/2_2_infer_grounding.py`

- Grounding-DINO 使用 `box_threshold=0.25`、`text_threshold=0.35`；
- `present` 和 `no-exist` 分别推理；
- 输出只保留检测到的 phrase 集合；
- 使用 `device='cuda'`；
- 没有框质量校准、多个阈值一致性或跨检测器确认。

#### `data_pipeline/2_3_image_filter_dino.py`

- `present` 中未被检测到的对象被删除；
- `no-exist` 中被检测到的对象被删除；
- 任一侧变为空就丢弃样本；
- 主要按列表下标连接 caption 与 detection，而不是严格按 `idx` 连接；
- 使用精确字符串匹配，未处理同义词、复数、词形变化和检测框置信度。

因此，“未检测到”在这条数据流水线中直接被当成“对象不存在”，这是论文数据合成阶段可接受但不适合当前几何仲裁的强假设。

#### `data_pipeline/3_1_1_query_cpq_generate.py`

- 通过 DeepSeek-V2 生成 CPQ/TPQ；
- 使用 BGE-M3 记忆库避免相似问题；
- 线程并发默认 `100`；
- 温度为 `0.9`；
- 依赖外部 API 和生成式 JSON 解析。

#### `data_pipeline/3_1_2_query_cpq_filter.py`

- 通过 DeepSeek-V2 审查问题；
- 规则包括不能问抽象声音/季节/感受，不能生成不现实动作，CPQ 不能以 “How many” 开头，不能是一般存在性问题；
- 只检查输出字符串中是否含 `pass` 或 `reject`，没有严格结构协议。

#### `data_pipeline/3_1_3_query_cpq_process.py`

- 对 TPQ/CPQ 都构造“事实提示”；
- 提示内容明确告诉模型目标对象不存在，并要求拒绝回答。

这说明 Antidote 的收益来自强事实先验和训练，而不是单靠模型自行发现图像中没有对象。当前 DM-SMS-1 没有训练，因此只能吸收其“正反证据平衡”和“安全拒答”思想，不能直接声称拥有同类收益。

### 3.7 对当前第二点的可取内容

可取：

- 训练或决策中必须同时提供正例和反例；
- 只奖励否定会产生假阴性和过度谨慎；
- 正反假设要平衡；
- 应记录真实存在对象被误拒的风险；
- 原始模型回答和纠正回答需要独立保存，避免事后无法审计。

不可直接迁移：

- Grounding-DINO 未检出不能直接当作强反证；
- CPQ/TPQ 的文本问答任务不等于三维实例类别仲裁；
- DPO/LoRA 训练需要新合同、独立校准和 GPU，不适合当前运行时修补；
- 论文中的 CP-Bench 分数不能直接作为当前类别换类正确率。

## 4. FairJudge：评价模型的顺序偏置

论文：`Large Language Models are not Fair Evaluators`。

### 4.1 实验发现

作者让 GPT-4/ChatGPT 比较两个回答，只交换回答位置，不改变内容。结果显示严重的位置偏置：

- GPT-4 在 Vicuna-13B 对 ChatGPT 的比较中，Vicuna 放在第一位时胜率 `51.3%`，放在第二位时只有 `23.8%`，冲突率 `46.3%`；
- ChatGPT 在同一比较中，Vicuna 放第一位胜率 `2.5%`，放第二位胜率 `82.5%`，冲突率 `82.5%`；
- 当两个答案质量差距很小时，交换顺序造成冲突的概率更高；
- 先输出评价证据、再输出分数，比先给结论后解释更稳定。

### 4.2 校准方法和指标

作者提出：

1. 多证据校准（MEC）：多次生成评价证据和分数；
2. 平衡位置校准（BPC）：交换答案位置并平均；
3. 人在回路校准（HITLC）：优先把高位置熵样本交给人工。

ChatGPT 对人工多数意见的一致性：

| 方法 | 准确率 | Kappa |
|---|---:|---:|
| 原始单次评价 | 44.4% | 0.06 |
| 证据优先 | 52.6% | 0.23 |
| MEC，k=3 | 53.2% | 0.24 |
| MEC，k=3 + BPC | 58.7% | 0.31 |
| MEC，k=3 + BPC + 20%人工 | 71.3% | 0.52 |

### 4.3 对当前代码的直接对应

当前 AB/BA 双顺序是正确的必要防线，但它只解决“候选顺序位置偏置”，不能解决：

- 候选名称本身产生的语义先验；
- 模型把环境关系误当成目标属性；
- 模型在两种顺序下重复同一个错误；
- 模型对“没有证据”和“存在反证”不作区分。

当前代码应继续保持 AB/BA，但未来新合同最好保存：

- 两种顺序的逐候选证据文本；
- 支持证据视角集合；
- 反证证据视角集合；
- 两种顺序证据的语义重合度；
- 若证据不一致，则 no-op。

### 4.4 不能直接照搬的地方

FairJudge 评价的是回答质量，不是视觉事实。其人工一致率也只有 `71.7%`，说明即便人工判断也不是绝对真值。当前项目不能把 LLM 自评或 GPT 裁判当成类别真值，只能把它当作无 GT 风险门。

## 5. Large Language Models Are Not Robust Multiple Choice Selectors：选项位置偏置

论文：`Large Language Models Are Not Robust Multiple Choice Selectors`（PriDe）。

### 5.1 主要结果

作者在 20 个语言模型、多个选择题数据集上发现，模型会偏好某些选项字母，而不是只依据选项内容。例如在平衡的 1,000 个 MMLU 样本中，LLaMA-30B 选择 A/B/C/D 的比例为 `34.6%/27.3%/22.3%/15.8%`，明显偏离均匀分布。

把正确答案移动到固定位置，可以使准确率大幅变化。论文提出 PriDe：通过少量样本估计选项位置先验，再进行无标签推理时去偏。

### 5.2 对当前第二点的含义

AB/BA 双顺序确实有必要，因为候选编号、名称顺序和回答位置都可能影响模型。但当前双顺序只是把顺序偏置暴露出来，并不能估计一个稳定的全局先验。

当前安全原则应是：

- 两种顺序都支持，才允许进入候选竞争；
- 若两种顺序结果不一致，保持原类别；
- 不要对所有样本事后估计一个“模型偏爱第一个候选”的全局修正再写回当前运行；
- 任何位置先验校准都必须在新独立合同中预注册。

## 6. Consistency and Uncertainty：黑盒模型的邻域一致性

论文：`Consistency and Uncertainty: Identifying Unreliable Responses From Black-Box Vision-Language Models for Selective Visual Question Answering`。

### 6.1 方法

作者无法访问黑盒视觉语言模型的内部概率，因此训练一个较小的视觉问题生成器，为同一图像和问题生成多个语义近似的表面改写，再把这些改写送给黑盒模型。若模型在改写问题上回答一致，则认为风险较低；若不一致，则拒答或交给专家。

### 6.2 主要结果

在 VQAv2、OK-VQA 和对抗性 AdVQA 上：

- 一致性越高，回答风险通常越低；
- 一致性可以改善风险—覆盖率曲线；
- 对分布外和对抗样本仍有帮助，但相关性比普通分布弱；
- 高一致性不保证答案正确，因为模型可能稳定地重复一个语言先验错误；
- 五个改写通常提供较好的稳定性和成本折中。

### 6.3 对当前第二点的建议

当前 AB/BA 可以被看作一种极小的语义邻域测试，但还不是完整一致性测试。未来独立分支可考虑：

```text
固定属性证据
→ 少量语义等价问题改写
→ 检查支持/反证是否稳定
→ 与 AB/BA 顺序稳定共同作为风险门
```

不过，这会增加 Qwen 调用次数，必须在新合同中固定调用预算；不能在当前 7,006 条运行中插入。

## 7. Verbalized Uncertainty：模型自报把握度不可靠

论文：`Know What You Do Not Know: Verbalized Uncertainty Estimation Robustness on Corrupted Images in Vision-Language Models`。

### 7.1 实验设置

作者对 GPT-4V、Gemini 和 Claude 施加高斯噪声、失焦模糊和 JPEG 压缩等图像损坏，要求模型同时输出答案和置信度，再计算准确率、置信度和 ECE。

### 7.2 结果

- 图像损坏越严重，准确率通常下降；
- 置信度不一定同步下降；
- 三个模型普遍过度自信，错误答案也常有 `80%～100%` 的置信度；
- 高严重度下 ECE 变差；
- 拒答率更高的模型有时具有更好的准确率和校准误差；
- 95% 置信区间通常不能被当作统计意义上的真实置信区间。

### 7.3 对当前合同的结论

当前证据中的 `confidence` 只能用于记录和审计，不应单独决定换类。尤其不能实施：

```text
confidence > 0.8 → 视为支持
confidence < 0.5 → 视为反证
```

当前更加合理的语义是：把握度是证据强弱的附加字段，必须与可观察内容、视角支持、正反证据和双顺序稳定性共同使用。

## 8. More Thinking, Less Seeing：长思考可能削弱视觉 grounding

论文：`More Thinking, Less Seeing? Assessing Amplified Hallucination in Multimodal Reasoning Models`。

### 8.1 核心发现

作者比较 Qwen2.5-VL 基础模型和多个推理增强模型，在 MMVP、MMEval-Pro、VMCBench、Bingo、MMHAL 等感知/幻觉数据上观察到：

- 推理模型在感知任务上的幻觉普遍高于非推理基础模型；
- 推理链越长，视觉词元注意力越低，指令和语言词元注意力越高；
- 模型更容易用场景共现和语言先验替代视觉证据；
- 推理长度与准确率通常呈先升后降的非单调关系；
- 适合数学或复杂推理的长度，不一定适合对象存在和细粒度属性判断。

### 8.2 对当前属性阶段的启示

当前属性提示应继续：

- 不要求“逐步思考”；
- 不要求长解释；
- 只要求短英文观察、视角编号、支持和缺失证据；
- 先视觉事实，后候选仲裁；
- 对不清晰对象允许 `unknown`，不要用长推理补全。

若未来使用 Qwen3-VL thinking 版本，必须另测视觉注意、链长、拒答率和错误类型，不能因为推理能力更强就默认它更适合当前任务。

## 9. When Thinking Hurts：思考链不一定是可靠不确定性

### 9.1 关键结果

在 POPE 对抗集上比较 Qwen3-VL-8B-Thinking、Qwen3-VL-8B-Instruct、GLM-4.1V-9B-Thinking 和 InternVL3-8B：

| 模型 | 准确率 | 不清楚/拒答 | 幻觉样本数 | 答案熵 AUROC | 思考熵 AUROC |
|---|---:|---:|---:|---:|---:|

| Qwen3-VL-8B-Thinking | 71.0 | 22% | 34 | 0.492 | 0.647 |

- 严格有效率；
- 安全回退率；
- 候选替换覆盖率；
- 换类比例；
- 独立正例保持能力。

不能只报告“错误没有增加”，也不能只报告换类数。

## 12. Rethinking Visual Neglect / CAS：更多视觉依赖不一定更好

论文：`Rethinking Visual Neglect in Vision-Language Models`，包含 CAS（Context-Aware Steering）相关实验。

### 12.1 主要结论

- 增加视觉依赖不一定减少幻觉；效果随模型和任务变化；
- Qwen-VL 生成任务中报告 `(alpha=+1, beta=-1)`；
- 二分类任务中报告 `(alpha=+1, beta=+1)`；
- 只验证了对象存在，不充分覆盖属性和关系；
- 需要隐藏层注入、额外校准和 GPU。

### 12.2 对当前项目的结论

不能简单通过“把视觉特征权重调大”解决类别错误。当前已有多视角 Alpha、YOLO、SigLIP、ProxyCLIP 的失败和迁移结果也支持这一点：问题不是单纯视觉比例不足，而是：

- 目标是否真正落地；
- 证据是否直接指向目标；
- 视角是否独立；
- 类别候选是否足够；
- 同类副本竞争是否安全。

当前不建议增加隐藏层注入或视觉 steering。

## 15. Details Matter 与 Alpha-CLIP：主分类和 SMS 的正确合同

论文：`Details Matter for Indoor Open-Vocabulary 3D Instance Segmentation`，论文及补充材料位于 `/tmp/details_matter_2507.23134.pdf` 等文件。

### 15.1 Alpha-CLIP 多视图合同

对 proposal `k`，在最高可见率视角集合 `V_k` 和三个尺度 `L` 上提取 Alpha-CLIP 特征：

\[
F_k = Norm\left(\sum_{v\in V_k}\sum_{l\in L}\alpha_{v,k} f^l_{v,k}\right),
\]

其中 `alpha` 是当前视角中 proposal 可见 3D 点数占 proposal 全部点数的比例。

ScanNet200 实现要点：

- top-20 可见图像；
- 3 个尺度；
- expansion ratio `0.2`；
- projected 2D box + SAM Alpha mask；
- visible-ratio 加权聚合；
- Alpha-CLIP 作为完整主分类器，而不是只作为 YOLO 的辅助证据。

### 15.2 SMS 公式

对场景中的 `K` 个 unique geometry proposal 和类别 `c`：

\[
\mu_c=\frac{1}{K}\sum_k L_{k,c},\qquad
\sigma_c=\sqrt{\frac{1}{K}\sum_k(L_{k,c}-\mu_c)^2}.
\]

令 `c_max=argmax_c L_{k,c}`，则：

\[
SMS_k=\frac{L_{k,c_{max}}-\mu_{c_{max}}}{\sigma_{c_{max}}}.
\]

如果 `SMS_k < tau_SMS`，论文直接从最终 predictions 删除该 proposal。

### 15.3 表 7 指标

| 分类配置 | AP | AP50 | AP25 |
|---|---:|---:|---:|
| proposals + CLIP | 27.5 | 34.7 | 38.2 |
| + Alpha-CLIP | 30.5 | 37.6 | 41.1 |
| + SMS filtering | 32.7 | 41.4 | 45.3 |

### 15.4 与项目历史的差异

项目过去的 Z2/Z3/NCS 主要把 Alpha 当辅助软证据或已有 representative 内的 score-swap 证据，没有完整复现 top20 × 3-scale × 0.2 expansion 的主分类合同。NCS-5 的 SMS-inspired z-score 没有真正删除 proposal，因此不能据此否定论文 SMS。

但 DM-SMS-1A 已经按独立 NCS-train100 合同完成，Alpha main 相对 frozen control 有一定提升，但 SMS tau0 未通过预注册 gate，并且删除集中度失败。因此不能继续扫描阈值，也不能用论文的 `[-1,1]` 稳定范围在当前数据上反向选阈值。

## 17. OV3D-CG、OpenTrack3D、Group3D、PTC、AttrSeg

这些论文是当前未来 NCS-7 方向的重要依据。

### 17.1 OV3D-CG

核心结论是完整场景上下文比孤立目标裁剪更有帮助。论文记录的对象 patch 结果约 `15.5 AP`，在完整场景中使用 SAM 高亮目标后约 `22.7 AP`。

对当前项目：

- 双栏图（完整场景红框 + 同视角局部裁剪）是合理的；
- 只给局部 crop 容易丢失放置关系和功能线索；
- 只给完整场景又容易把邻近物体误归为目标；
- 当前双栏输入兼顾两者，但仍需用目标指向审计防止环境污染。

### 17.2 OpenTrack3D

论文记录的 CLIP 约 `22.9 AP`，Qwen3-VL MLLM 约 `26.0 AP`。这说明 MLLM 有助于开放词汇理解，但不支持无门控地让 MLLM 全量重写类别。

对当前项目：

- MLLM 适合作为冻结候选内的后验仲裁器；
- 不适合改变 geometry、mask 或 proposal 数量；
- 必须有 abstain/no-op 和候选集合限制。

### 17.3 Group3D

语义兼容 grouping 优于完全无类别 grouping 或严格同名 grouping。它支持把空间关系、相邻物体和语义兼容性作为证据，但当前项目不能据此直接合并几何节点。

### 17.4 PTC

训练自由的 prototype-guided text calibration 对 ProxyCLIP 报告平均约 `+1.9 mIoU`。但其原型、阈值和数据分布具有数据集依赖，只能作为未来辅助校准对照，不能在 val312 上选参数。

### 17.5 AttrSeg

把类别拆成形状、材质、部件、用途和关系属性，有助于细粒度区分。例如：

- `office chair` 与 `chair`：轮子、靠背、扶手、可坐功能；
- `desk` 与 `table`：抽屉、办公布局、键盘/显示器关系；
- `counter` 与 `table`：靠墙、连续台面、柜体或厨房设备关系。

这支持当前“先无类别属性、后有限候选仲裁”的两阶段设计。

## 18. DROP-CLIP / 3D Feature Distillation with Object-Centric Priors

论文：`3D Feature Distillation with Object-Centric Priors`，本地文件 `/tmp/object_priors_2406.18742.pdf`。

### 18.1 方法

论文提出 DROP-CLIP，在多视角 RGB-D 中：

1. 使用二维实例掩码隔离对象级 crop；
2. 只在对应三维实例 mask 内融合特征；
3. 用语义 informativeness 衡量视角质量，剔除无信息或噪声视角；
4. 通过大规模 MV-TOD 合成数据蒸馏为单视图可用的三维特征。

### 18.2 论文证据

论文核心不是把所有视角等权平均，而是强调：

- 遮挡、杂乱背景和局部 crop 会产生噪声；
- 对象级 mask 能减少 patchyness；
- 语义引导的视角选择能提高 grounding 和分割清晰度；
- 对象级空间先验应进入特征融合，而不是只在后处理阶段补救。

### 18.3 对当前第二点

当前最多 3 个互补视角、最高可见率优先、随后最大化相机中心距离，方向上与论文一致。可以保留：

- 视角可见率；
- 目标 mask 支持；
- 相机几何独立性；
- 视角间证据一致性。

但当前不能重新扫描视角数或 mask 规则，因为它们已经冻结在运行合同中。

## 19. 黑盒一致性、候选顺序和模型置信度的统一解释

三类论文共同说明：

### 19.1 位置一致不等于事实正确

FairJudge 和 PriDe 说明模型可能在位置、编号、候选名称顺序上有稳定偏置。AB/BA 可减少偏置，却不能消除同一个语言先验错误在两种顺序下重复出现。

### 19.2 高把握度不等于高正确率

Verbalized Uncertainty 说明模型自报置信度严重过度自信。`confidence` 必须是辅助信息。

### 19.3 多次改写一致不等于事实正确

Consistency and Uncertainty 说明一致性是风险信号，但稳定重复的场景共现错误仍可能发生。

### 19.4 最安全的证据层级

当前最合理的证据层级是：

```text
直接、目标指向、可见、跨视角一致的支持/反证
  > 单视角描述
  > 模型自报 confidence
  > 候选名称出现后的语言推断
```

## 21. 精读后的综合分析

### 21.1 当前第二点的主要瓶颈不是“视觉信息太少”

多篇论文最初看起来都可能支持增加视觉信息、增加视角或增强模型推理，但综合阅读后，真正瓶颈更具体：

1. 目标与环境的证据边界不清；
2. “没有观察到”被错误升级为“类别不存在”；
3. 候选名称引入文本先验；
4. 模型会稳定地重复场景共现错误；
5. 正确对象和反事实对象的拒答代价不对称；
6. 同一 geometry 的类别副本会放大一个错误决定；
7. 高置信度和长推理都可能掩盖视觉错误。

因此，继续增加模型规模、增加长思考或单纯提高视觉权重，都不是当前最优先的改动。

### 21.2 当前 AB/BA 是必要条件，但不是充分条件

AB/BA 解决了顺序位置偏置这一类问题，FairJudge 和 PriDe 都支持它。但如果模型在两种顺序下都看到同一个错误，AB/BA 会把错误稳定化，而不是发现错误。

所以双顺序必须与以下条件组合：

- 替代类别双顺序支持；
- 替代类别没有强反证；
- 冻结原类别双顺序都有强反证；
- 支持和反证来自目标本身而非环境；
- 缺失、遮挡和不清晰只能是 unknown；
- 两种顺序的证据文本和支持视角不能严重冲突。

### 21.3 当前安全回退不是“保守过度”，但必须监测覆盖率

Antidote、HalluVL-DPO 和 When Thinking Hurts 都说明，过度否定可以提高反幻觉指标，却损害真实对象召回或一般能力。当前安全回退的价值是防止错误写入冻结类别，但若所有复杂样本都回退，第二点就会退化为 no-op。

因此完整账本完成后应记录但不在运行中调参：

- 严格有效率；
- 属性拒绝率；
- 候选集合外比例；
- 安全回退率；
- 双顺序不一致率；
- 提议换类率；
- 按类别和场景的换类集中度；
- 原类别被否定的证据类型。

### 21.4 “原类别双强反证”是当前最值得优先验证的结构修改

它同时吸收了：

- Antidote 的正反样本平衡；
- HalluVL-DPO 对假阴性风险的警告；
- Visual Evidence Prompting 的“证据可能缺失”；
- FairJudge 的双顺序校准；
- Verbalized Uncertainty 对 confidence 不可靠的结论。

它不需要重新训练 Qwen，也不改变 geometry、候选、视角和分数。若在当前运行完成后要开新分支，这是最小、最容易审计、理论风险最低的候选。

### 21.5 第二优先级是“证据一致性”，不是“更多推理”

若原类别双强反证仍不足，可另行预注册少量固定语义改写或证据复述任务：

```text
同一视角与属性输入
→ 固定的两到三个等价问题
→ 检查支持/反证是否稳定
→ 与 AB/BA 结果取交集
```

这比引入长链思考、增加隐藏层 steering 或下载更大模型更容易控制。但它会显著增加调用量，必须在新合同中单独预算。

## 22. 后续修改路线建议（必须另行预注册）

### 路线 A：原类别双强反证门（首选）

建议逻辑：

```text
alternative.supported_AB = true
alternative.supported_BA = true
alternative.strong_counterevidence_AB = false
alternative.strong_counterevidence_BA = false
incumbent.strong_counterevidence_AB = true
incumbent.strong_counterevidence_BA = true
→ change class
otherwise → keep incumbent
```

注意：

- 原类别“未被支持”不等于原类别强反证；
- 只有直接、清晰、目标指向、跨视角一致的反证才可置 `strong_counterevidence=true`；
- 缺失、遮挡、模糊、视角不足、候选集合不足都不得置为强反证；
- 需要扩展账本字段，分别保存 incumbent 和 alternative 的证据；
- 不能在当前运行中途加入。

### 路线 B：双顺序 + 证据文本一致性

增加证据一致性门：

- AB/BA 对同一类别的支持视角至少有一个交集；
- 关键支持事实的文本语义不能互相矛盾；
- 一边认为“清晰可见”，另一边认为“遮挡严重”时 no-op；
- 证据来自环境关系而不是目标本身时 no-op。

该路线只应作为 A 的辅助，而不是替代 A。

### 路线 C：有限语义改写一致性

仅在 A/B 仍不足时考虑。每个 geometry 固定少量改写，不允许自由生成无限问题。只有改写结果、AB/BA 和属性证据都稳定时才允许换类。

风险：调用量增加、改写器自身可能引入新类别或问题语义偏移，因此必须严格限制问题模板。

### 路线 D：独立视觉证据源交集

可考虑在后续独立合同中使用已有 Alpha-CLIP、SigLIP、ProxyCLIP 或固定视觉复核，但仅作为支持/反证交集，不改变 geometry。

不要把多个模型的分数简单相加；应记录：

- 各源对原类别和替代类别的独立支持；
- 各源缺失状态；
- 视角和 mask 是否相同；
- 多源冲突时 no-op。

### 路线 E：训练型方法

当前不推荐。若未来训练，应参考 Antidote 的正反平衡和 DPO，但必须：

- 独立训练/校准/测试场景；
- 正确对象接受样本与反事实拒答样本平衡；
- 报告覆盖率、假阴性和一般能力；
- 控制 LoRA 强度，避免过度谨慎和模型崩溃；
- 不使用 validation60/val312 选参数。

## 23. 不建议的修改

以下方向虽然在某些论文中有效，但不适合当前阶段：

1. 把 `confidence` 设阈值后直接换类；
2. 把“没有观察到”直接设为 `strong_counterevidence`；
3. 只增加否定提示或只训练 CPQ；
4. 删除 TPQ/真实正例平衡；
5. 引入长链思考或“请逐步推理”；
6. 让 MLLM 新增第三类别；
7. 用单帧 top-1 覆盖多视角 geometry 类别；
8. 把同一 geometry 的 600 个类别副本当作独立 SMS population；
9. 依据当前运行中失败样本修改合同；
10. 在 safety60 或 val312 上选阈值、prompt、模型或拒答比例；
11. 直接下载 Qwen3-VL 并替换当前 Qwen2.5-VL；
12. 通过增加调用次数掩盖严格输出合同本身的问题。

## 25. 最终结论

精读大量论文、补充材料、图片和公开代码后，当前第二创新点最可靠的判断不是“需要更强模型”，而是：

```text
必须把视觉证据、反证、未知状态、顺序偏置和拒答风险分开建模。
```

当前已经完成并应保留的内容：

- 双栏目标输入；
- 多视角互补选择；
- 属性与类别分阶段；
- 候选名称隐藏于属性阶段；
- 有限候选集合；
- AB/BA 双顺序；
- 严格单对象 JSON；
- 一次固定重写；
- 无效安全回退；
- 不修改 geometry、mask、membership 和 score。

当前最应该在运行结束后另行验证的修改：

```text
替代类双顺序支持
+ 替代类无强反证
+ 原类别双顺序强反证
→ 才允许换类
```

第二优先级是证据文本和视角一致性；第三优先级才是有限语义改写或独立视觉源交集。训练、长链思考、隐藏层 steering、换模型和大规模提示调参都不应成为当前运行的临时修补。

本文记录的是论文依据和研究判断，不是对当前运行结果的准确率结论。当前 DM-SMS-1 完成后，必须先完成原始输出独立审计、安全决定账本、单候选合并和完整账本审计，之后才能决定是否为路线 A 建立新的预注册分支。
