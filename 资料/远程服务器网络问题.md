从截图看，主要原因仍是远程 Codex无法连接供应商：

```text
Reconnecting... waiting for network
Connection failed: error sending request
```

结合你之前的配置，最可能是：

```text
远程 Codex
→ 远程 127.0.0.1:15721
→ SSH RemoteForward
→ 本地 cc-switch
```

其中反向端口转发再次断开。VS Code终端仍可使用，只能证明普通 SSH连接正常，不能证明15721反向转发正常。

先不要点击底部垃圾桶或播放按钮，也不要重跑 AP。

### 一、远程服务器检查15721

在 VS Code远程终端执行：

```bash
ss -ltnp | grep ':15721'
```

再执行：

```bash
curl -sS -o /dev/null \
  -w 'HTTP=%{http_code}\n' \
  --connect-timeout 5 \
  --max-time 15 \
  http://127.0.0.1:15721/v1/models
```

判断：

- 没有监听、`Connection refused`：SSH反向转发没有建立。
- 请求超时：反向转发存在，但转发链路或本地 cc-switch失效。
- `HTTP=200`：网络已经恢复，可能只是 Codex扩展进程保留了失效连接。

### 二、本地电脑检查 cc-switch

在本地终端，不是远程终端，执行：

```bash
curl -sS -o /dev/null \
  -w 'HTTP=%{http_code}\n' \
  --connect-timeout 5 \
  --max-time 15 \
  http://127.0.0.1:15721/v1/models
```

应该返回：

```text
HTTP=200
```

如果本地200、远程失败，就可以确定是 SSH反向转发断开。

### 三、检查是否有重复 SSH连接

在本地终端执行：

```bash
ps -eo pid,ppid,etime,args |
grep -E '[s]sh.*(FenGe|10\.91\.28\.4|22892)'
```

再执行：

```bash
code --status 2>/dev/null | grep -E 'Window \('
```

如果存在多个 `OpenYOLO3D [SSH: FenGe]` 窗口，先通过 `Alt+Tab` 找到旧窗口，正常执行：

```text
文件 → 关闭窗口
```

不要直接杀掉所有 SSH或 VS Code进程。

### 四、手动恢复反向转发

如果本地15721正常而远程不正常，在本地新终端运行：

```bash
ssh -vvv -N FenGe
```

保持这个终端打开。看到类似内容说明成功：

```text
remote forward success for: listen 15721, connect 127.0.0.1:15721
```

随后回到远程终端重新测试：

```bash
curl -sS -o /dev/null \
  -w 'HTTP=%{http_code}\n' \
  http://127.0.0.1:15721/v1/models
```

返回200后，在 VS Code命令面板执行：

```text
Developer: Reload Window
```
