# 固定GD10纠错消融独立审计

2026-10-12。审计对象为`fi1_local_edit_ablation_development200_20261012_v1`。原训练、预测、门限及失败结论均未修改。没有新训练或新部署；新增推理、关闭门和GT筛查均为本目录隔离诊断。

## 核验结论

原A/A0/B/C主要数值可以复现。未发现导致这些数字失真的点集执行或池级IoU汇总错误。但“训练内已拟合删除，问题进一步落在折外泛化”需要收窄；高删除召回不能证明可靠删除，且40轮20样本pilot不能替代12轮正式模型的训练集表现。

本次实际完成：

- 20份合同源码、11份冻结SL、200份GT、30份正式模型/历史、20份pilot模型/历史、400份预测、400份条件、400份标签资产哈希检查。
- 独立重放6396个动作、5252个匹配身份父IoU，核对1599个封存A复用。
- 使用独立直方图IoU实现重算56268个完整NT/只补/只删的目标结果，与原CSV一致。
- 重新运行11项单元测试，全部通过。
- 对3个严重案例的A0/B/C做9次CPU模型重放，动作一致，最大概率差0.00048828125。
- 在每折原先封存的20个训练内pilot候选上运行正式12轮A0/B/C模型，共300次额外CPU前向；这些是正式模型训练子集诊断，不是新训练，也不是全量训练集评测。
- 读取并检查训练程序、原五折模型/数据隔离逻辑、40轮pilot和12轮正式训练关系；未把pilot作为正式模型初始化或外折选轮。

A0控制合理：A训练双臂，B-A0才隔离训练监督改变。新代码使用独立逐轮随机数产生候选排列，A0/B/C候选顺序一致。C-B仍同时改变表示、辅助损失和推理门；不能把整体差异单独归给身份表示。

## 发现一：B的“平衡”是很强的目标重加权

`tools/fi1_local_edit_ablation_core.py:26`将4096点监督按固定分层质量分配；点少时有放回抽样，`balanced_loss`直接传给原CE、Dice和保持损失，没有按采样概率恢复原点分布。

395个具有可见删除监督的父候选中，删除点相对均匀全域抽样的期望质量放大中位数约15.40倍、最大4354倍；57个候选只有不超过10个删除点。最大单点期望重复约1365次/批候选。例：scene0627_01/c005，34832个邻域点中2个删除监督点被分配约1024个样本。

这符合本轮合同，不是实现偏离；但它不是单纯让稀有点更常被看见，而是改变了优化分布。均衡样本上的Dice和好父保持项也随之变化。沿用原0.8门并不能保证相同的真实分布精度。实际因果还包含有限样本、特征与优化，不能声称单一机制解释全部误删。

## 发现二：训练内也没有证明“可靠删除”已经解决

40轮小样本B pilot的已知删除精度为58.43%、87.34%、86.72%、74.36%、99.77%；召回虽约96%—98%，多折同时删除大量目标。C无候选门的pilot也有误删，例如fold2删对10005点、误删2143点。

进一步用正式12轮模型，在原100个训练内候选—折绑定上测试：

|正式模型，候选门关闭|删除召回|已知删除精度|
|---|---:|---:|
|B，训练子集|49.58%|82.29%|
|C，训练子集|52.68%|73.03%|

同一子集的已保存OOF结果另存`formal_train_subset.json`。此子集按既有训练GT层/hash选择，并非全量训练集，不能从中精确估计全训练总体；但足以否定“正式模型训练纠错已经可靠，仅剩折外泛化”的强表述。训练目标、拟合质量、阈值精度与泛化同时有问题。

## 发现三：C主要减少动作量，没有改善删除点的纯度

用已保存C概率关闭候选门，不改点门、可见性或最小点数：

|诊断|B|C关闭候选门|C正式输出|
|---|---:|---:|---:|
|动作数|1149|1174|309|
|正确删除污染|25266|23624|1685|
|误删目标|53124|50785|3581|
|已知删除精度|32.23%|31.75%|32.00%|
|好父IoU损失>.10|16|28|7|
|纯删除池增益≥.02|0|0|0|
|只补池价值目标|7|11|4|

C门允许312/1599候选，309个实际编辑；阻止96个父IoU可提升≥.02的提议，也阻止150个会退化>.02的提议。减少了错误数量，但正确删除也按接近相同比例减少，删除精度仍约32%。C去门并非可部署方案，严重退化反而更多。

`candidate_scope`监督的是稳定父身份下、使用GT理想编辑可否提升至少.005；`repair`却用该类别概率许可当前网络的真实动作。这两个任务不同。即使后置使用完全正确的现有scope标签，C删除池级增量仍为0。因此把六类分类准确率从55.66%提高到100%，也不能自动证明删除有效。

## 发现四：候选资格与逐点监督存在目标不一致

本轮新增outside_scope/ambiguous等候选类别，但逐点y继续沿用“最大有效GT IoU、至少20交点”的旧目标；B对这些点做强纠错，C仍用相同逐点损失，同时候选头学习拒绝此候选。

|后置候选类别|父内可见污染点数|B正确删除|B误删目标|
|---|---:|---:|---:|
|edit|32071|7301|33629|
|keep|549|94|17449|
|outside_scope|85186|6686|340|
|ambiguous|34699|11129|1626|

153126个删除机会点中，119885个、约78.29%，来自outside_scope或ambiguous。数量很多不等于池价值高：后置可见理想删除诊断中，outside_scope没有≥.02池级目标，edit仍有89个。原120个整体删除上界和各scope子集上界可能有目标重叠，不能相加。

这不是说outside_scope所有点都没GT，也不是说应在推理读GT删候选。含大面积地板但与小物体有20点交集的父候选，可能被逐点监督要求把地板删掉以追逐那个小物体，而候选头要求拒绝它。下一版训练应先区分可确定的当前实例、范围外/未标注与身份含糊，避免将任意最佳GT交集都当成强实例条件。

`scope_oracles.json`使用与上轮一致的全GT理想修改口径，允许删除GT非目标但未标注为有效实例的点；C scope标签生成则保留unknown点。因此scope=keep也可能在该更乐观oracle里有收益，不能拿这张后置表直接替换监督或当学习结果。

## 发现五：整个候选的动作开关粒度太粗

原NT全部保留时，从一组固定完整编辑中拒绝某些候选不能增加该组完整点集的池覆盖。因此，对本版B/C完整删除动作，即使一个完美的接受/拒绝门，也不能把已经为0的删除池增量变成正数。需要改变动作本身或动作组合粒度。

对B已执行删除逐点做GT后置筛查，仅保留已知其他实例点，可出现9个≥.02删除池增量目标；这说明一部分正确编辑被同次错误编辑抵消。但逐点GT筛查不能部署。

进一步采用不读GT的动作划分：将已有概率>=.8且两组可见的拟删除点，按冻结原始8邻接图划分连通块。再用GT仅评价哪些完整块可用：

|完整删除块的后置诊断|B|C关闭候选门|
|---|---:|---:|
|只保留没有目标标注点的块，池增益≥.02|7|3|
|更严格：块内全部为已知其他实例，池增益≥.02|4|2|

严格版本不把未知标注当正确污染。该诊断在原始点概率上形成块，位于最终最小100点判定之前；最终不足100点仍回退父候选。是一个可行GT筛选方案，不是最优上界、学习效果或新正式输出。它给出的有效信息是：当前预测里已经存在一些可以整体取用的局部删除块，正确块与错误块可以分开评价。

## 下一步建议

不建议继续提高删除配额、增加全帧观测，或只把C候选头换得更大。优先做一个目标明确的实验：**对具体局部删除块预测实际收益与误删风险**。

1. 固定GD10输入、父候选、0.15米域和原物理五折；保留A/A0/B/C封存结果。首先只研究删除，补点独立保存/评价，避免再次互相抵消。
2. 用固定的逐点提议产生局部删除块；输入块本身、周边保留点、父候选和竞争实例关系。验证对象是“删除这一块会怎样”，不是“这个父候选理论上可不可修”。上述8邻接划分可作为第一版固定提案，不按GT拆块或挑样本。
3. 训练标签来自实际建议动作的目标损失、污染删除及IoU变化；身份不确定的候选不赋予任意单一目标的强纠错标签，应使用拒绝/不确定监督。候选资格与点/块监督要一致。
4. 学习与门限必须在外层训练折内部完成。若用生成器预测来训练验证器，应在外层四个训练折内部再交叉生成，不能直接混用本轮全局OOF预测训练下一层：其他外折模型可能见过当前外层留出场景GT，造成堆叠泄漏。当前保存OOF结果只用于本次后置诊断。
5. 先验证训练内已知删除精度与误删尾部，而不仅是召回。样本均衡与真实分布损失分开处理，防止少数纠错点上千次重复支配损失；若仍使用分层采样，需明确重要性权重/代价目标，Dice与保持项可在完整点域上计算，置信度在训练内部留出上校准。
6. 正式评测比较原完整动作、原C门与局部块验证。首先看是否首次产生可靠删除池增量；最终仍按原保守几何门、好候选尾部和身份漂移验收。不通过则不接SL。块的GT机会有限，不能保证实际学习保留这4个目标；如果连该版本也不能区分，就应改归属特征/边界表示，不继续堆开关或按外折结果调门。

这个实验同时有明确停止点：如果只有更少动作、更高表面精度却没有真实删除池增量，就不能称为几何推进。新增块级训练尚未启动。
